# 회사 PC 수집기 설치 안내서 v1

- 날짜: 2026-10-29 (Asia/Seoul)
- 대상: 회사 PC에 workmcp **수집기**를 관리자 권한 없이 설치하고 운영 서버로 올리는 단계(피터가 직접 따라 한다)
- 근거: `doc/planning/2026-10-29_M6-설계_v1.md` §3(묶음)·§4(안내서)·§5(업데이트), `README.md`, `workmcp setup` 최종 형태
- 쓰는 법: 각 단계는 **명령 → 기대 결과 → 안 될 때** 순서다. 에이전트는 회사 PC를 조작하지 않는다. 막히면 우회하지 말고 멈춘다.
- 자리표시자: `<VPS_HOST>`(운영 서버 호스트 이름), `<USER>`(Windows 사용자 이름), `<MCP_TOKEN>`·`<PUSH_TOKEN>`(서버가 한 번만 보여 주는 값). 실제 값은 이 문서에 적지 않는다.
- 명령은 모두 **PowerShell**(앱 밖 Windows Terminal)이다. 회사 PC의 출력은 회사 밖으로 가져오지 않고 **건수와 코드**만 전달한다.

## 0. 시작 전에

| 확인 | 이유 |
|---|---|
| 운영 서버가 이미 떠 있고(`doc/guides/2026-10-26_VPS-배포절차서_v1.md`), 서버 쪽 토큰 발급(`token issue`)을 할 수 있다 | 5·9단계에서 쓴다 |
| 회사의 AI 사용 규정이 이 도구(추출 텍스트를 내 VPS에 저장, 조각을 Claude·Codex로 전달)를 허용한다 | 준수는 사용자의 책임이다 |
| 처음 올릴 문서 폴더 **하나**(작은 것)를 정했다 | 7단계. 처음부터 큰 폴더로 시작하지 않는다 |
| 이 도구는 원본을 읽기만 한다 | 그래도 처음에는 작은 폴더로 건수를 확인한다 |

## 1. 사전 확인: Python, 폴더 위치, 서버 연결

```powershell
py -0p
python --version
$env:OneDrive
curl.exe -s -o NUL -w "%{http_code}`n" https://<VPS_HOST>/workmcp/healthz
Test-NetConnection <VPS_HOST> -Port 443 | Select-Object TcpTestSucceeded
netsh winhttp show proxy
$env:HTTPS_PROXY ; $env:HTTP_PROXY
```

| 항목 | 기대 | 안 될 때 |
|---|---|---|
| `py -0p` | `-V:3.12 ...` 줄이 있다 | 없으면 2단계 |
| `$env:OneDrive` | 비어 있거나 `...\OneDrive...` | OneDrive 아래 폴더(문서·바탕화면 리디렉션 포함)에 코드·데이터 홈을 두지 않는다. 아래 3·5단계 위치를 쓴다 |
| `curl.exe` | `401` (토큰 없는 요청을 서버가 거절한다 = **서버까지 도달함**) | 아래 "프록시 확인" |
| `TcpTestSucceeded` | `True` | `False`면 443이 막혀 있다 |
| `netsh winhttp show proxy` | `Direct access (no proxy server).` | 프록시가 나오면 아래 |

### 프록시 확인 (중요)

`push`는 **프록시를 쓰지 않고** 서버에 직접 HTTPS(443)로 연결한다(수집기의 유일한 외부 연결). 따라서:

- `curl.exe`가 `401`을 내고 `TcpTestSucceeded`가 `True`면 직접 연결이 된다. 계속한다.
- 연결이 안 되고 `netsh winhttp show proxy`나 인터넷 옵션에 프록시 서버가 있다면, 회사가 프록시를 강제하는 것이다. **여기서 멈추고 피터에게 알린다.** (`push`에 프록시 지원을 넣는 것은 설계 변경이라 별도 결정이 필요하다. 환경변수를 바꿔 우회하려 하지 않는다.)
- 모델 다운로드(4단계)와 pip 설치는 `HTTPS_PROXY` 환경변수를 존중하므로 프록시 환경에서도 동작할 수 있다. 막히면 오프라인 묶음을 쓴다.

## 2. Python 3.12 설치 (없을 때만)

python.org에서 **Windows installer (64-bit) 3.12.x**를 받아 실행한다(서명된 설치기, 관리자 권한 불필요).

- 설치기의 "Use admin privileges"·"Install for all users"(모든 사용자용) 항목은 켜지 않는다. 사용자 단위 설치가 기본이며 관리자 권한이 필요 없다.
- "Add python.exe to PATH"는 켜도 되고, 켜지 않아도 `py -3.12`로 부른다.

```powershell
py -3.12 --version
```

기대: `Python 3.12.x`. 설치기가 막히거나 회사 앱 제어가 차단하면 피터가 IT에 확인한다(우회하지 않는다).

## 3. 코드 받기

`C:\Users\<USER>\workmcp\`처럼 **OneDrive 밖**의 로컬 폴더에 둔다.

**온라인 (주 경로)**

```powershell
cd C:\Users\<USER>
git clone <저장소 URL> workmcp
cd workmcp
```

`git`이 없거나 막히면 GitHub의 "Download ZIP"을 받아 같은 위치에 푼다. 그것도 막히면 **오프라인 묶음**을 쓴다.

**오프라인 묶음 (예비 경로)**

다른 PC에서 만든 묶음(`workmcp-bundle-...` 폴더 또는 zip, 모델은 `workmcp-model-bge-m3-...` 폴더)을 USB 등으로 가져와 `C:\Users\<USER>\workmcp-bundle\`에 푼다. 먼저 검증한다.

```powershell
cd C:\Users\<USER>\workmcp-bundle\<묶음 폴더>
python -I verify_bundle.py .
certutil -hashfile SHA256SUMS SHA256
```

| 기대 | 안 될 때 |
|---|---|
| 마지막 줄이 `ok N mismatch 0 missing 0 unlisted 0`이고 종료 코드 0 | `mismatch`·`missing`·`unlisted`가 있으면 **설치하지 않는다**. 묶음을 다시 만들어 가져온다 |
| `certutil`이 낸 해시가 묶음을 만든 PC에서 본 값(`INSTALL.txt`에도 적혀 있음)과 같다 | 다르면 묶음이 바뀐 것이다. 설치하지 않는다 |

`python`이 없으면 `py -3.12 -I verify_bundle.py .`로 부른다.

## 4. 설치 (가상환경 + 해시 고정)

pip의 해시 검사(`--require-hashes`)를 끄지 않는다. `--no-deps`는 프로젝트 자신(`workmcp`)을 설치하는 줄에만 쓴다(의존성은 앞 줄이 해시 고정으로 이미 설치).

**온라인**

```powershell
cd C:\Users\<USER>\workmcp
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --require-hashes -r requirements.lock.txt
.venv\Scripts\python.exe -I -m pip install --no-deps .
.venv\Scripts\python.exe -I -m pip check
```

**오프라인 (묶음 폴더 안에서)**

```powershell
py -3.12 -m venv C:\Users\<USER>\workmcp\.venv
$py = "C:\Users\<USER>\workmcp\.venv\Scripts\python.exe"
& $py -I -m pip install --no-index --find-links wheels --require-hashes -r requirements.lock.txt
& $py -I -m pip install --no-index --find-links wheels --no-deps workmcp==0.0.1
& $py -I -m pip check
```

| 기대 | 안 될 때 |
|---|---|
| `Successfully installed ...`, `pip check`가 `No broken requirements found.` | `THESE PACKAGES DO NOT MATCH THE HASHES`: **멈춘다.** 해시 검사를 끄지 않는다. 묶음/네트워크를 의심하고 피터에게 알린다 |
| | 보안 소프트웨어가 설치 중 파일을 막으면 한 번 다시 시도하고, 그래도 막히면 피터가 IT에 확인한다(우회하지 않는다) |
| | 오프라인에서 `Looking in indexes`가 로그에 보이면 `--no-index`가 빠진 것이다 |

이후 모든 명령은 이 가상환경의 파이썬을 쓴다. 아래는 `$wm`을 정의해 둔다(새 창을 열 때마다 다시 정의).

```powershell
$wm = "C:\Users\<USER>\workmcp\.venv\Scripts\python.exe"
& $wm -I -m workmcp doctor
```

기대: `workmcp 0.0.1`, `env: clean`, `venv: ...`, `data home: ... (rules ok; not created yet)`. 아직 홈이 없어도 정상이다. `warning: env: PYTHONPATH is set` 같은 줄은 `-I`가 막아 주지만, 가능하면 그 변수를 비운다.

## 5. 데이터 홈 위치와 setup

데이터 홈(DB, 모델, 로그, 설정, push 토큰)의 기본 위치는 `C:\Users\<USER>\Motive_work`(`%USERPROFILE%\Motive_work`)다. 규칙(위반하면 `setup`이 아무것도 만들지 않고 종료 코드 2):

- 저장소·묶음 폴더 안이면 안 된다. 동기화 폴더(OneDrive 등)·UNC(`\\서버\...`)·상대 경로·AppData 아래도 안 된다.
- 회사에서 `%USERPROFILE%`이 네트워크/로밍 경로이면 로컬 드라이브를 쓴다. 예: `D:\Motive_work` (`--home D:\Motive_work`).

먼저 **미리보기**로 무엇을 할지 본다(아무것도 만들지 않는다).

```powershell
& $wm -I -m workmcp setup --home "$env:USERPROFILE\Motive_work" --model download `
    --source "C:\Users\<USER>\문서\작은폴더" --push-url https://<VPS_HOST>/workmcp --dry-run
```

괜찮으면 `--dry-run`을 빼고 실제로 실행한다. 모델은 **처음부터 최종 방식으로** 정한다(`config.toml`은 처음 한 번만 만들어지고 `setup`이 나중에 고치지 않는다).

```powershell
# 온라인: 모델 다운로드 (약 2.3 GB, 중단되면 이어받기)
& $wm -I -m workmcp setup --home "$env:USERPROFILE\Motive_work" --model download `
    --source "C:\Users\<USER>\문서\작은폴더" --push-url https://<VPS_HOST>/workmcp

# 오프라인: 모델 묶음 폴더에서 복사 (네트워크 없음)
& $wm -I -m workmcp setup --home "$env:USERPROFILE\Motive_work" --model-from "C:\Users\<USER>\workmcp-bundle\workmcp-model-bge-m3-5617a9f6" `
    --source "C:\Users\<USER>\문서\작은폴더" --push-url https://<VPS_HOST>/workmcp
```

기대 출력의 핵심 줄(경로의 사용자 이름은 환경에 따라 다름):

```
data home: C:\Users\<USER>\Motive_work (rules ok; created)
config: written ...\config.toml (sources 1, model bge-m3, push url set)
push token: missing - write the one line ... (Notepad) or set WORKMCP_PUSH_TOKEN
model bge-m3: ok (4 files, ..., SHA-256 verified)
clients: ... (등록 명령줄 출력. 아직 실행하지 않는다 - 9단계)
setup done (exit 0)
```

| 종료 코드·증상 | 뜻 | 대처 |
|---|---|---|
| 2 + `home_unc` | 홈이 네트워크 경로 | `--home`을 로컬 드라이브로 |
| 2 + `home_sync_component` / `home_sync_env` / `home_sync_attr` | 홈이 동기화 폴더(OneDrive 등) 아래 | 동기화되지 않는 로컬 폴더로 |
| 2 + `home_inside_repo` | 홈이 코드 폴더와 겹침 | 코드 폴더 밖으로 |
| 2 + `home_relative` / `home_trailing_dot_space` | 상대 경로 / 끝이 점·공백인 폴더 이름 | 절대 경로, 이름 수정 |
| 2 + AppData | AppData 아래 홈은 `--yes` 없이는 거부 | AppData 밖으로. 앱 가상화로 클라이언트마다 다른 DB를 보게 될 수 있다 |
| 4 | 인자·`--source` 폴더 없음·`--push-url`이 https가 아님 | 메시지의 인자를 고친다 |
| 1 + `model bge-m3: failed (model.onnx_data: sha256_mismatch)` | 다운로드 파일 손상 | 같은 명령을 다시 실행(이어받기·재검증). 반복되면 오프라인 묶음 |
| 1 + `HTTP 403` / `HTTP 407` | 회사 프록시·보안 장비가 Hugging Face를 막음 | 오프라인 모델 묶음(`--model-from`). 우회하지 않는다 |
| 이미 `--model none`으로 실행했다 | `config.toml`의 `[index] model`이 `none` | 메모장으로 `[index]`의 `model = "bge-m3"`로 직접 고치고 모델을 다시 `setup --model ...`로 받는다 |

설정 파일 `C:\Users\<USER>\Motive_work\config.toml`을 열어 `[[sources]]` 한 줄과 `[push] url`을 확인한다(`setup`은 이미 있는 설정은 고치지 않고, 빠진 줄을 "add:"로 알려 준다).

## 6. push 토큰

1. **서버에서** 피터가 수집기 이름을 정해 토큰을 발급한다(예: `<수집기 이름>` = 회사 PC를 알아볼 이름). 평문은 이때 **한 번만** 보인다.
   ```
   workmcp token issue --kind push --name <수집기 이름>
   ```
2. 평문을 메모장으로 `C:\Users\<USER>\Motive_work\push.token`에 **한 줄**로 저장한다(공백·줄바꿈 중간 없음). 파일은 홈 안에 있어야 한다. 채팅·메일·문서·git·셸 명령줄에 붙여 넣지 않는다.
   - 대안: 사용자 환경변수 `WORKMCP_PUSH_TOKEN`(8단계의 환경 변수 화면과 같은 방법).
3. 확인:
   ```powershell
   & $wm -I -m workmcp doctor
   ```
   기대: `role: collector`, `[push] url https://<VPS_HOST>/workmcp  token: ...`에서 출처가 `file`(또는 `environment`)로 표시된다. `missing`이면 파일 위치·이름(`push.token`)을 확인한다.

## 7. 작은 폴더 1개로 수집 → 색인 → 전송

```powershell
& $wm -I -m workmcp sources
& $wm -I -m workmcp scan
& $wm -I -m workmcp index
& $wm -I -m workmcp verify
& $wm -I -m workmcp push --dry-run
```

| 단계 | 기대 | 안 될 때 |
|---|---|---|
| `sources` | 수집 폴더와 그 상태가 나온다 | 폴더 이름이 틀리면 `config.toml`의 `[[sources]]` 경로를 고친다 |
| `scan` | `added N` 등 요약, 종료 코드 0 | 3 = 다른 스캔이 도는 중. 4 = 폴더·설정 오류. 파싱 실패 파일은 오류가 아니라 기록이다 |
| `index` | 청크·벡터 생성 요약. 첫 실행은 모델 로드와 임베딩으로 오래 걸린다. 큰 폴더는 `--limit N`으로 나눠 밤에 | `runtime_import_failed` = onnxruntime DLL을 보안 소프트웨어가 막음 → 어휘 검색만 가능, IT 확인. `model_missing` = 5단계 모델 |
| `verify` | `binding ok`, 종료 코드 0 | 1 = 원본이 그 사이 바뀌었거나 결속 실패. 줄에 나온 문서를 다시 `scan` |
| `push --dry-run` | `documents changed N`. **N이 예상과 같은지 확인한다**(작은 폴더의 파일 수 근처). 아무것도 보내지 않는다 | 아래 push 종료 코드 표 |

N이 맞으면 전송한다. 두 번째 실행은 `up to date`여야 한다.

```powershell
& $wm -I -m workmcp push
& $wm -I -m workmcp push
```

기대: 첫 push는 `sent: documents ...` 줄, 두 번째는 `up to date (batches 0, bytes sent 0 ...)`.

| `push` 종료 코드 | 뜻 | 대처 |
|---|---|---|
| 0 | 완료(`up to date` 포함) | — |
| 1 | 일부 문서·배치 거부(`refused: 경로 : 코드` 줄) | 코드를 본다. `version_too_large`·`too_many_parts`는 그 문서가 너무 큼(나머지 문서는 정상으로 올라간다). 문서 이름이 아니라 코드와 건수만 피터에게 전한다 |
| 2 | 데이터 홈 규칙 | 5단계 표 |
| 3 | 다른 `push`가 진행 중(`push.lock`) | 끝나길 기다린다. 6시간 넘게 갱신이 없을 때만 오래된 잠금으로 본다 |
| 4 | 설정·토큰 없음, 또는 서버와 스키마/청크 버전이 다름(`update the server first`) | 토큰은 6단계, 버전 불일치는 서버를 먼저 업데이트(아래 업데이트 절) |
| 6 | 서버에 연결할 수 없음(재시도 후) | 1단계의 직접 연결 확인. 프록시 강제면 멈추고 알린다 |
| 7 | 서버 TLS 인증서 검증 실패(재시도 안 함) | 회사가 TLS를 가로채 사설 CA를 쓰는 경우일 수 있다. IT에 확인. 검증을 끄지 않는다 |
| 401/403 줄 | `invalid_token`·`wrong_token_kind`(mcp 토큰을 넣음)·`collector_retired` | 6단계 토큰이 push 종류인지, 수집기가 은퇴하지 않았는지 서버에서 `workmcp collectors`로 확인 |
| `root_owned_by_other_collector` | 같은 폴더를 다른(은퇴하지 않은) 수집기가 이미 올림 | 아래 "수집기 교체" |

## 8. 클라이언트 연결 (Claude Code, Codex)

서버에서 **mcp 토큰**을 발급한다(push 토큰과 종류가 다르고, push 토큰은 MCP 경로에서 거부된다). Codex용은 별도 토큰을 권한다(클라이언트별 폐기 가능).

```
workmcp token issue --kind mcp --name <클라이언트 이름>
```

### 사용자 환경변수 (Codex용, 관리자 권한 불필요)

Windows 시작 메뉴에서 **"계정의 환경 변수 편집"**을 검색해 연다(영문: "Edit environment variables for your account"). **"시스템 환경 변수 편집"은 관리자 권한이 필요하니 쓰지 않는다.** 위쪽 "사용자 변수"에서 **새로 만들기** → 이름 `WORKMCP_MCP_TOKEN`, 값은 mcp 토큰. 확인을 누르고 **Codex를 다시 시작**한다(새 터미널 창도 다시 연다).

### Claude Code

`claude`가 PATH에 없으면 `Get-Command claude`로 위치를 찾고, 앱에 동봉된 경우 그 `claude.exe`의 전체 경로를 쓴다. 토큰이 명령줄에 들어가므로 **먼저 이 창의 기록 저장을 끈다**.

```powershell
Set-PSReadLineOption -HistorySaveStyle SaveNothing
claude mcp add --transport http --scope user workmcp https://<VPS_HOST>/workmcp/mcp --header "Authorization: Bearer <MCP_TOKEN>"
claude mcp list
```

> **주의:** `Remove-Item (Get-PSReadLineOption).HistorySavePath` 같은 기록 삭제 명령은 토큰이 든 한 줄이 아니라 **PowerShell 명령 기록 파일 전체**를 지운다(전에 쓴 명령이 모두 사라진다). 이미 토큰을 친 뒤라면 PowerShell 창을 모두 닫은 다음, 그 파일(`(Get-PSReadLineOption).HistorySavePath`가 가리키는 텍스트 파일)을 메모장으로 열어 토큰이 든 줄만 지우는 쪽이 낫다. 위의 `SaveNothing`을 먼저 설정하면 이 문제가 생기지 않는다.
>
> 토큰을 명령줄에 아예 쓰고 싶지 않으면, 프로젝트 폴더의 `.mcp.json`에 `"Authorization": "Bearer ${WORKMCP_MCP_TOKEN}"` 형태를 쓰는 방법이 있다(`doc/examples/mcp-remote.json.example`). 사용자 범위(`~/.claude.json`)에서 `${VAR}` 확장이 되는지는 확인되지 않았다.

### Codex

```powershell
codex mcp add workmcp --url https://<VPS_HOST>/workmcp/mcp --bearer-token-env-var WORKMCP_MCP_TOKEN
codex mcp list
```

그다음 `C:\Users\<USER>\.codex\config.toml`을 메모장으로 열어 `[mcp_servers.workmcp]` 블록에 두 줄을 더한다(`doc/examples/codex-config-remote.toml.example` 참고).

```toml
[mcp_servers.workmcp]
url = "https://<VPS_HOST>/workmcp/mcp"
bearer_token_env_var = "WORKMCP_MCP_TOKEN"
startup_timeout_sec = 30
tool_timeout_sec = 120
```

기존의 다른 `[mcp_servers.*]` 블록은 건드리지 않는다. `codex`가 PATH에 없고 데스크톱 앱만 있다면 앱의 MCP 설정 화면에서 같은 값을 넣거나, 위 블록을 `config.toml`에 직접 붙여 넣는다.

| 증상 | 대처 |
|---|---|
| 클라이언트에서 401 | 토큰 종류(mcp), 환경변수 이름 `WORKMCP_MCP_TOKEN`, 환경변수 설정 뒤 클라이언트 재시작 |
| 서버가 목록에 없음 | `claude mcp list` / `codex mcp list`, Codex는 `config.toml` 블록 확인 |
| 첫 검색이 느림 | 서버가 모델을 읽는 중(수십 초). Codex는 위 `tool_timeout_sec = 120` |

## 9. 확인

1. 각 클라이언트에서 **새 세션**을 열고 `status` 도구를 부른다. 기대: `role: server`, 수집기의 문서 수가 7단계 건수와 맞는다.
2. 올린 폴더의 내용으로 `search`를 한다. 기대: 조각마다 출처(파일, 위치)가 붙고, 응답의 `delivered_sources`가 이번에 서버를 떠난 조각 전부와 같다.
3. 무엇이 나갔는지 보려면: `push` 보고서의 `sent` 줄, 서버 `status`의 수집기 문서 수, 클라이언트 응답의 `delivered_sources`.

이상이 없으면 `[[sources]]`에 실제 폴더를 더해 단계적으로 넓힌다(폴더 추가 → `scan` → `index` → `push --dry-run`으로 N 확인 → `push`).

## 10. 정기 실행 (선택)

원하면 작업 스케줄러(사용자 권한)에 밤마다 `scan → index → push`를 건다. 명령은 모두 `C:\Users\<USER>\workmcp\.venv\Scripts\python.exe -I -m workmcp ...` 형태다. 이전 실행이 아직 돌면 `push`는 종료 코드 3(잠금)으로 기다리지 않고 끝난다.

## 11. 업데이트 (서버 먼저, 수집기 나중)

프로토콜·스키마·청크 버전이 다르면 `push`가 종료 코드 4로 안전하게 거절된다. 그러므로 순서를 지킨다.

1. **서버**: `doc/guides/2026-10-26_VPS-배포절차서_v1.md`의 코드 반입 → `pip install --no-deps` → `systemctl stop workmcp` → `workmcp setup --home <홈> --upgrade`(백업·마이그레이션·doctor) → `systemctl start workmcp`. 진행 중인 push가 없는지 `workmcp collectors`로 먼저 본다.
2. **수집기**: `scan`·`index`·`push`가 돌고 있지 않은지 확인(홈에 `*.lock` 없음) →
   - 온라인: `git pull`, 의존성 파일이 바뀌었으면 `pip install --require-hashes -r requirements.lock.txt`, 이어서 `pip install --no-deps .`
   - 오프라인: 새 묶음을 3단계처럼 검증하고 4단계 오프라인 pip 두 줄
   - 그다음 `& $wm -I -m workmcp setup --home "$env:USERPROFILE\Motive_work" --upgrade`, 이어서 `push --dry-run`(종료 코드 0이면 호환)
3. 서버를 다시 시작했으면 Claude Code·Codex에서 **새 세션**을 연다(도구 목록은 세션 시작 때 정해진다).
4. 되돌리기: 서버는 배포 절차서의 되돌리기 절, 수집기는 옛 코드로 pip 재설치(DB는 `--upgrade`가 만든 `db\backup-...sqlite3`로 복원 가능).

## 12. 수집기 교체 (retire)와 후임

수집기를 바꾸거나 PC를 교체할 때 서버에서 옛 수집기를 은퇴시키면 그 push 토큰이 폐기된다. **올린 데이터는 지워지지 않고 남는다.**

```
workmcp collectors retire <옛 수집기 이름>
workmcp token issue --kind push --name <새 수집기 이름>
```

**운영 규칙(V3-4): 후임 수집기는 은퇴한 수집기와 같은 루트 키로 등록한다.** 즉 새 PC의 `[[sources]]` 폴더 경로를 옛 수집기와 **완전히 같은 경로**로 둔다(대소문자는 무시된다). 경로가 같아야 새 수집기가 옛 문서를 이어받아 갱신·삭제를 반영한다. 상위·하위 폴더로 바꾸거나 다른 경로로 옮기면, 옛 경로의 문서는 삭제 반영 범위에 들어가지 않아 서버에 `active`로 남을 수 있다. 경로를 바꿔야 하면 먼저 피터와 상의한다. 살아 있는(은퇴하지 않은) 다른 수집기가 같은 폴더를 올리고 있으면 `root_owned_by_other_collector`로 거부된다.

## 13. 문제가 생기면 확인할 것

| 확인 | 명령·위치 |
|---|---|
| 환경 전체 | `& $wm -I -m workmcp doctor` (홈 규칙, 가상화, 환경 오염, 저장소, 색인, 모델, 역할, `[push]`, 토큰 출처, 수집 폴더) |
| 단계별 로그 | `C:\Users\<USER>\Motive_work\logs\scan-·index-·push-YYYYMMDD.log` (본문 없음, 경로·해시·코드만) |
| 종료 코드 | scan·index: 0, 2 홈, 3 잠금, 4 설정 / push: 0, 1, 2, 3, 4, 6, 7 / verify: 0, 1 / setup: 0, 1, 2, 3, 4 |
| 결속 | `& $wm -I -m workmcp verify` 실패 줄 |
| 가상화·환경 경고 | `doctor`의 `app virtualization`, `warning: env:` 줄 |
| 진단 테스트 | 묶음의 `src.zip`을 다른 폴더에 풀어 `& $wm -I -m pytest -q` (그 폴더를 데이터 홈으로 쓰지 않는다) |

회사 PC의 출력은 회사 밖으로 가져오지 않고 건수와 코드만 전달한다. 토큰은 어떤 로그·채팅·문서에도 적지 않는다.
