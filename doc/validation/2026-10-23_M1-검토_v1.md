## 4. 확인 항목별 판단 (요청 2~6)

### 4.1 원본 읽기 전용 (요청 2)
- 원본을 여는 곳은 `collect.read_source`·`stream_sha256` 두 곳뿐이고 둘 다 `open(path,'rb')`다(`collect.py:55,68`). `binding`도 `read_source`만 쓴다(`binding.py:41`). 파서는 bytes만 받고 pypdf·olefile·zipfile은 `io.BytesIO`를 받는다(`_container.py:35,142`, `hwp.py:110`, `pdf.py:35`). 압축 해제는 메모리에서만 한다.
- `test_scan_and_verify_never_write_to_sources`가 전 파일 읽기 전용 속성 + 감사 훅 아래 scan→verify→scan을 돌려 위반 0건, 원본 지문(size·mtime_ns·sha256·속성·목록) 불변, 읽기 `open`이 모두 `'r'`임을 단언하고 통과한다. 현재 코드의 쓰기 시도는 **0건**으로 고정됐다.
- 구멍은 검사 쪽에만 있다(M1-L2 정적, M1-L3 런타임). 공유 모드 부작용은 M1-L1.

### 4.2 증분 수집 정확성 (요청 3)
- 추가·변경·touched·삭제·복원·A→B→A·이동(삭제+추가, 해시 재사용)·`unstable`(읽기 전후 stat 비교)·`locked`(자리 sha `'0'*64`, 다음 스캔 채움)은 코드와 테스트가 일치하고 1.2에서 실측했다.
- 부분 실패: 읽지 못한 폴더 아래는 삭제하지 않고(`collect.py:353-360,414-419`), 예외·중단 시 열린 배치를 되돌리고 삭제 판정을 하지 않는다(`:456-468`). 파일 하나의 문서·버전·단위는 같은 배치라 "버전만 있고 단위 없음"이 생기지 않는다. 남은 `running` 행은 다음 스캔이 `aborted`로 고친다. 경계는 M1-L6.
- 같은 sha256 재사용은 `parser_version`·`parse_status='ok'`·단위/글자 상한을 함께 본다(`:177-183`). `.txt`·`.md`가 같은 `text-1`을 쓰는 것 말고는 확장자마다 버전 문자열이 달라 다른 파서의 단위를 가져오지 않는다. 재사용은 설정으로 바꿀 수 있는 상한(`max_units`·`max_text_chars`)을 모두 본다. 안전하다.
- `scan.lock`: `O_CREAT|O_EXCL`, 24시간 지난 잠금만 경고 후 제거, `os.kill` 없음, `finally` 해제. 내용 없는 잠금은 파일 시각으로 판단해 경쟁 시 거부 쪽으로 기운다. 적절하다.
- 대소문자만 바뀐 이름은 M1-L5.

### 4.3 파서 안전성·정확성 (요청 4)
- 예외 누수 없음: 디스패처가 모든 예외를 `failed/exception:<Class>`로 바꾸고 메시지를 버린다(`parsers/__init__.py:187-193`). P6~P9에서 확인했다. 단위 모양·서로게이트·`locator.check_unit`을 저장 전에 검사한다(`:161-171,194`).
- zip: 항목 수·선언 크기 합 상한, 멤버 경계 읽기, 위조 크기는 zipfile이 끊는다(P6). 압축 해제 누적은 선언 크기 합(512 MiB)으로 묶인다. XML: DTD 이중 방어(P7), 깊은 중첩 안전(P8), PPTX 그룹 재귀는 `RecursionError`로 격리(P9). HWP 레코드 길이는 남은 길이로 검사(`hwp.py:74-91`). PDF는 pypdf 한도(P5).
- 메모리는 상한이 실제로 작동하지 않는다: **M1-1**.
- 본문 유출: 스캔 stdout·로그·`parse_error`에 표지 토큰 없음(1.2, `test_scan_output_and_log_carry_no_document_text`). olefile의 `print`는 덤프 함수에만 있고 호출하지 않는다. olefile·pypdf 로거는 처리기가 있어 lastResort(stderr)로 가지 않는다.
- locator: 단위 좌표는 결정적이고 `verify`가 같은 바이트에서 다시 만들어 비교한다. 중복 가능성은 M1-L8, 첨부 메일은 M1-L9, Strict OOXML은 M1-L10.

### 4.4 결속 검사의 의미 (요청 5)
- 덮는 것: `parse_status='ok'`이고 현재 파일 sha256이 같은 버전의 단위(순서·kind·locator·텍스트·해시)·청크·근거 인용. 안 덮는 것: 파서가 원문을 옳게 읽었는지, 파일이 바뀐 옛 버전(stale), ok가 아닌 버전. `not_ok`는 단위가 0개라 결속할 것이 없고, `stale`은 원본을 보관하지 않으므로 재검증할 방법이 없다 — 제외가 정당하다.
- 파서가 비결정적이면 scan 때 단위와 verify 때 재도출이 달라 실패로 잡힌다(캐시는 같은 verify 안에서만). DB 단위 위조(텍스트·해시·locator·개수)는 `test_binding.py`의 위조 테스트들이 잡는다. 허술하게 통과하는 경우는 M1-L7(검사 0건에도 ok, 상태 위조).
