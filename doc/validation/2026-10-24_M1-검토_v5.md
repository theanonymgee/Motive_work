### 1.2 M1-10 XLSX 정상 문서 오거부 해소 (검토자 `v4r\bin\g4_xlsx.py` 재생성 → `v3r\probe.py`)

시트 1개, A열에 서로 다른 공유 문자열(합성 한글 자유 텍스트), 행마다 셀 1개. 단위·텍스트 상한 안.

```
xlsx_100k_200.xlsx file 1224 KiB -> ok/None units=100000 1.8s peak_commit=120 MiB (base 26 MiB, +93 MiB)    # 20 M자
xlsx_120k_250.xlsx file 1617 KiB -> ok/None units=120000 2.3s peak_commit=151 MiB (base 26 MiB, +124 MiB)   # 30 M자 (v4: limit_memory 오거부)
xlsx_190k_150.xlsx file 2400 KiB -> ok/None units=190000 3.6s peak_commit=186 MiB (base 26 MiB, +160 MiB)   # 28.5 M자 (v4: limit_memory 오거부)
xlsx_199k_250.xlsx file 2684 KiB -> too_large/zip_part units=0 1.0s peak_commit=132 MiB (base 28 MiB, +104 MiB)  # 49.75 M자 (아래 참고)
```

v4에서 `limit_memory`로 오거부되던 12만×250자·19만×150자가 이제 ok다. 피크 +93~160 MiB로 G1(784 MiB, 보관 상향 뒤 식 912 MiB) 안. 보관 모델이 실제 크기(`sys.getsizeof`+8 B)로 바뀌어 과대 계수가 사라졌다.

참고(지적 아님): 19.9만×250자(49.75 M자, 텍스트 상한 50 M 안)는 `zip_part`로 거부된다 — sharedStrings 압축 해제가 142 MiB로 파트 상한 `zip_max_part_bytes`(128 MiB)를 넘기 때문이다. 이는 M1-10과 무관한 기존 zip 파트 상한이고(이번 커밋이 바꾸지 않음), 고정 코드·피크 안전이라 G 위반이 아니다. 다만 설계 §15.2 M1-10의 "19.9만×250자 ok +209 MiB" 서술은 한글 자유 텍스트 생성기로는 재현되지 않는다(정상적으로 `zip_part`) — 문서 정확성 메모. 핵심 두 사례(12만×250·19만×150)는 설계가 적은 +124/+157과 일치(+124/+160).

### 1.4 B-1 PDF 객체 스트림·내용 스트림 증폭 차단 (검토자 `v5r\pdf\genpdf.py`, 합성)

압축된 작은 파일로 pypdf가 크게 부풀릴 세 변형(B1f 계열 — 압축하지 않은 비스트림 객체 — 은 제외):

```
objstm_tree_12m.pdf   file 103 KiB -> too_large/pdf_stream 0.3s peak_commit=166 MiB (base 25, +140 MiB)   # 객체 스트림 속 쪽 트리 1,200만 참조
objstm_widths_12m.pdf file  23 KiB -> too_large/pdf_stream 0.3s peak_commit= 77 MiB (base 25, + 52 MiB)   # 객체 스트림 속 글꼴 /Widths 1,200만
operands_12m.pdf      file  23 KiB -> too_large/pdf_stream 0.4s peak_commit= 76 MiB (base 24, + 52 MiB)   # 내용 스트림 피연산자 1,200만
```

세 변형 모두 pypdf가 파싱하기 전에 디코드 구문 토큰을 세어 `pdf_stream`으로 끊는다. 피크 +52~140 MiB(+140은 객체 스트림 ≤75 MB 디코드 자체). v4 보류 시 실행자 추정(+1.3~4 GiB)을 모두 G1 안으로 막았다. 대조로, 상한을 올려(`_PAGE_TOKENS`·`_OBJECT_STREAM_TOKENS`=10^9) 사전 계수를 끄면 같은 입력이 실제로 커진다:

```
normal_ops_300000.pdf  -> ok 6.6s  peak +312 MiB (사전 계수 끔; ~90만 연산자, ~3 M 토큰)
normal_ops_1000000.pdf -> ok 22.8s peak +1012 MiB (사전 계수 끔; ~300만 연산자) → 사전 계수 켜면 pdf_stream +75 MiB로 차단
```

300만 연산자 쪽(+1,012 MiB)은 사전 계수가 `pdf_stream`으로 정확히 막는다(G1 초과 방지). → 아래 M1-L21 참조.
