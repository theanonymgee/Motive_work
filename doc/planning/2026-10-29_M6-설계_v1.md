"공백·영폭 공백이 하나도 없는 8 Mi자 단위는 조각 버퍼가 단위 전체로 자라 서버 피크 약 +120 MiB, part당 약 1 s, 진행 행 7.9 MB 재기록 31회. 상한(`UNIT_MAX_CHARS`)이 서버에서 강제되고 `MemoryMax 3G`보다 훨씬 작아 받아들인다. 실제 문서에서 이런 단위는 거의 없다 [추정]."

### 1.2 V3-2 구현 메모

- `store.ELIGIBLE_VERSIONS`에 조건을 더하면 `index`(수집기)에도 걸리지만 수집기 store의 `push_parts`는 늘 비어 있어 결과가 같다 **[사실]** 표는 양쪽 스키마에 있음. 조건: `AND NOT EXISTS (SELECT 1 FROM push_parts p JOIN pushes s ON s.id = p.push_id JOIN collector_versions m ON m.collector_id = s.collector_id AND m.local_version_id = p.local_version_id WHERE m.version_id = v.id AND p.part = 0)` — `receive._in_progress`와 같은 조건이라 **그 함수 본문을 SQL 상수로 옮겨 둘이 하나를 쓴다**.
- 비용: 검색 후보 질의마다 `push_parts`(평소 0행) 조인 하나. 측정: `tests/test_search.py` 기존 p50 테스트가 있으면 전후 비교, 없으면 24만 행 합성에서 1회 측정해 반영 기록에 적는다.
- `verify --stored`는 `units` 행 없는 청크를 불일치로 보던 것이 사라진다(진행 중 버전 자체가 대상에서 빠짐).

### 1.3 V3-5 잠금 파일 형식

`{"pid": 123, "started_at": "...", "heartbeat_at": "...", "nonce": "<16 hex>"}`. 오래됨 판정은 `heartbeat_at`(없으면 `started_at`, 그것도 없으면 mtime). `scan.lock`·`index.lock`은 nonce 없이 쓰여도 되지만 같은 함수를 쓰므로 자연히 nonce가 들어간다(해롭지 않음). `release_lock(path)`(nonce 없음)는 옛 동작(무조건 삭제) — `scan`·`index` 호출부는 바꾸지 않아도 되지만, 실행자 B가 한 줄씩 nonce를 넘기도록 바꾸는 것을 권한다(등급 1 범위).

### 1.4 처리 뒤 확인 출력(총괄이 PLAN ②에 적을 것)

`uv run pytest -q tests/test_receive.py tests/test_push.py tests/test_store_schema.py tests/test_sync.py tests/test_search.py tests/test_network_boundary.py` 통과 줄 + 새 테스트 이름 목록. 네트워크 경계 테스트는 **고치지 않는다**(V3 수정은 import를 늘리지 않는다 — `push.py`에 `secrets`/`os.urandom`은 이미 `os` 사용 중, `time`도 있음 **[사실]**).

## 2. `workmcp setup` (수집기 역할 기준)

### 2.1 범위 — **[결정]**

`setup`은 **회사 PC 수집기**를 준비하는 명령이다. 서버(VPS) 설정은 M5 절차서가 끝냈고, 서버에서는 `--upgrade`만 쓴다(§5). 하는 일: ① 데이터 홈 검사·생성 ② `config.toml` 새로 쓰기(없을 때만) ③ 모델 준비(온라인 `--model download` / 오프라인 `--model-from`) ④ push 토큰 **위치 안내와 존재 확인** ⑤ 클라이언트 등록 **명령줄 출력** ⑥ `doctor` ⑦ 선택 `--scan`·`--index` ⑧ `--upgrade`(백업→마이그레이션→doctor).

하지 않는 일: 프로세스 생성(`claude`·`codex`·`setx`·pip 실행 0), 전역 클라이언트 파일(`~/.claude.json`·`~/.codex/config.toml`) 쓰기(키 이름만 읽음), 토큰 값 읽기·만들기·출력, 원본 파일 읽기, `config.toml` 수정(새 파일 1종만 — M1 "TOML 작성기 없음" 결정 유지), `[[sources]]` 자동 결정.

### 2.2 명령줄 (0단계 계약 + 추가 3개)

```
<PY> -I -m workmcp setup --home PATH
     (--model download | --model none | --model-from DIR)
     [--source PATH ...] [--push-url https://<VPS_HOST>/workmcp]
     [--clients claude,codex | --clients none] [--scope user|project] [--project DIR]
     [--scan] [--index] [--upgrade] [--yes] [--dry-run]
```

추가: `--push-url`(수집기 역할; `sync.url_problem` 통과해야 함, 아니면 exit 4), `--clients none`(`CLIENTS`에 `'none'` 허용 — 단독만), `--dry-run`(`plan()` 호출; 아무것도 만들지 않고 `planned`로 표시). `Options`에 `push_url: str | None`, `dry_run: bool` 필드 추가 → `tests/test_setup.py`의 `Options()` 비교·`check_options` 표에 세 줄 추가(실행자 C 소유).

### 2.3 단계별 동작·멱등성·출력

| 단계(`STEPS`) | 동작 | 다시 실행하면 | 출력 줄(값·경로·개수만) |
|---|---|---|---|
| `home` | `paths.validate_home(--home)` → 규칙 위반이면 **exit 2, 아무것도 안 만듦**. `paths.under_appdata`면 `--yes` 없이는 **거부 exit 2**(앱 가상화 때문; `--yes`면 경고 후 진행). 통과 시 `ensure_home`(db·models·logs·tmp) | `created False`, 변경 0 | `data home: C:\Users\<USER>\Motive_work (rules ok; created)` |
| `config` | 파일 **없으면** `config_template(sources, model, push_url)`로 생성: `[[sources]] path = '...'`(TOML 리터럴 문자열 — 역슬래시 그대로; `'`가 든 경로는 기본 문자열로 이스케이프), `[index] model = "bge-m3" \| "none"`, `[push] url = "..."`(있을 때). 각 `--source`는 `config.validate_root`로 검사(없는 폴더·네트워크·홈/저장소 겹침 → exit 4; 동기화 폴더는 경고만). **있으면 고치지 않고** 빠진 `--source`·`--push-url`을 "이 줄을 추가하세요"로 출력(상태 `done`, `changed False`). push 토큰: 값은 읽지 않고 `WORKMCP_PUSH_TOKEN` 설정 여부와 `<home>\push.token` 존재만 보고 안내 | 변경 0 | `config: written ...\config.toml (sources 1, model bge-m3, push url set)` / `config: exists, not changed; add: [push] url = "..."` / `push token: file push.token present` 또는 `push token: missing - write one line to C:\...\push.token (Notepad) or set WORKMCP_PUSH_TOKEN; the token is shown once by "workmcp token issue --kind push" on the server` |
| `model` | `--model download`: `download_model` → `models.fetch`(고정 리비전 URL 4개, `.partial` 이어받기, `HTTPS_PROXY` 존중, SHA-256 뒤 원자 교체) — **패키지의 유일한 네트워크 단계**. `--model-from DIR`: `models.import_from`(네트워크 0, 평면·저장소 레이아웃 모두 읽음). `--model none`: `[index] model = "none"` 템플릿, "어휘 검색만" 안내. 실패한 파일이 있으면 상태 `failed` → exit 1(다른 단계는 계속) | `already_verified`, 변경 0 | `model bge-m3: ok (4 files, 2,284,694,904 bytes, SHA-256 verified)` / `model bge-m3: failed (model.onnx_data: sha256_mismatch)` — 진행률은 `fetch`의 로그 줄(5%마다) |
| `clients` | **수집기 역할(`--push-url` 또는 기존 설정에 `[push] url`)**: 원격 등록 명령 출력(§2.5). **로컬 역할**(push url 없음): M5 설계 §2.3의 stdio 명령 출력. `registered()`가 `~/.claude.json`·`~/.codex/config.toml`에 `workmcp` 키가 있는지 **읽기만**(없거나 못 읽으면 `None`) 해 "이미 등록됨" 표시. `--scope project`: `<project>\.mcp.json`·`<project>\.codex\config.toml`을 **없을 때만** 생성(원격 템플릿 = `doc/examples/mcp-remote.json.example` 본문 + Codex TOML 블록), 있으면 같은지 비교 → 다르면 요약 + "`--yes`로 덮어쓰기" | 같은 내용이면 변경 0 | 명령줄 2~4개(§2.5) |
| `doctor` | `cli.doctor()`를 그대로 실행(홈·가상화·env 오염·store·index·model·role·`[push]`·토큰 출처·sources) | — | doctor 출력 그대로, `detail.exit_code` |
| `scan` / `index` | `--scan`이면 `cli.scan`(설정 sources, `scan.lock`), `--index`면 `cli.index_command`(모델 지연 로드). 기본은 **하지 않음** — 실제 폴더 수집은 피터가 명시적으로 켠다 | 증분 | 각 요약 줄 |
| `upgrade` | `--upgrade`만: ① `scan.lock`·`index.lock`·`push.lock`이 살아 있으면 exit 3 ② `backup_store`: `PRAGMA wal_checkpoint(TRUNCATE)` 뒤 `db\backup-YYYYMMDD-HHMM-v<옛 schema>.sqlite3`로 1 MiB 블록 복사(홈 안) ③ `store.open_home`(마이그레이션; 체크섬 불일치면 exit 2) ④ `doctor`. 다른 단계는 `skipped` | 백업 파일이 하나 더 생김(의도) | `backup: ...\db\backup-20261101-0900-v5.sqlite3 (12.3 MB)` / `schema: v5 -> v5 (no migration needed)` |

exit 코드: 0 모든 단계 `done`/`skipped`; 1 어느 단계 `failed`(모델 검증 실패, 백업 실패); 2 홈 거부(AppData 포함); 3 `--upgrade` 중 잠금; 4 인자(`check_options`), 잘못된 `--source`·`--push-url`, 모델 이름. **비대화식**: 묻는 일이 없다. 모든 결정은 인자로, 확인은 `--yes` 하나.

### 2.4 비밀값 규칙

- `setup`은 토큰 값을 **읽지 않는다**(`paths.read_token` 호출 없음; `os.environ.get(PUSH_TOKEN_ENV)`의 참/거짓만). 출력·로그·결과 dict 어디에도 토큰·URL 쿼리·헤더 값이 없다. 테스트: `apply` 결과를 JSON으로 덤프해 가짜 토큰 문자열이 없음을 단언(환경·파일에 가짜 토큰을 넣고).
- `fetch`가 찍는 줄은 파일 이름·바이트·백분율만 **[사실]**.
- 전역 파일 읽기(`registered`)는 키 이름 유무만 반환한다(헤더·토큰 값은 파싱 결과에서 버림).

### 2.5 수집기 역할의 클라이언트 등록 출력

```
# Claude Code (user scope) - run this yourself; <MCP_TOKEN> is the mcp token the server printed once
claude mcp add --transport http --scope user workmcp https://<VPS_HOST>/workmcp/mcp --header "Authorization: Bearer <MCP_TOKEN>"
#   (the token lands in your shell history: afterwards clear it, e.g. PowerShell: Remove-Item (Get-PSReadLineOption).HistorySavePath)
#   alternative without the token on a command line: a project .mcp.json with "Authorization": "Bearer ${WORKMCP_MCP_TOKEN}" (doc/examples/mcp-remote.json.example)

# Codex - run this yourself; the token stays in the environment variable, never on the command line
codex mcp add workmcp --url https://<VPS_HOST>/workmcp/mcp --bearer-token-env-var WORKMCP_MCP_TOKEN
#   then add to [mcp_servers.workmcp] in %USERPROFILE%\.codex\config.toml:  startup_timeout_sec = 30  /  tool_timeout_sec = 120

# the variable (user environment, no admin): Windows settings > "계정의 환경 변수 편집" > new WORKMCP_MCP_TOKEN
# check: claude mcp list / codex mcp list, then call the status tool in each client
```

- `<VPS_HOST>` 자리에는 `--push-url`의 호스트가 들어간다(출력은 실제 값; 저장소 문서에는 자리표시자).
- Claude Code 사용자 범위 `~/.claude.json`에서 `${VAR}` 확장이 되는지는 **[추정]**(문서는 `.mcp.json`에 대해 말함). 그래서 기본 출력은 `--header` 방식이고, 환경변수 방식은 프로젝트 범위 대안으로만 적는다. 실행자 E가 이 PC에서 사용자 범위 `${WORKMCP_MCP_TOKEN}`을 1회 시험하고 결과를 §7에 적는다.
- `claude` 명령이 PATH에 없는 PC(이 PC와 같음)에서는 앱 동봉 `claude.exe` 전체 경로를 쓴다(§4 안내서).

### 2.6 테스트(`tests/test_setup.py`, 실행자 C)

1. 멱등: 빈 임시 홈에 `apply` 2회 → 두 번째 결과 모든 `changed False`, 홈 아래 파일 목록·해시 동일, exit 0.
2. 거부: 저장소 안 홈 → exit 2, 폴더 생성 0; AppData 홈 `--yes` 없음 → exit 2; `--yes` → 경고 줄 + 진행; 없는 `--source` → exit 4; `http://` `--push-url` → exit 4; `--model latest` → exit 4(기존).
3. 설정 템플릿: 역슬래시·따옴표 든 경로가 `config.load`로 그대로 돌아옴(왕복); 기존 파일 있으면 바이트 불변 + "add:" 줄.
4. 모델: `--model-from`(가짜 4파일, 매니페스트 해시를 테스트가 덮어씀 — `test_models.py` 방식) → `ok`; 손상 → `failed` exit 1; `--model download`는 `opener` 주입으로 가짜 응답(`fetch(opener=)` **[사실]** 인자 있음) — 실제 네트워크 0.
5. 비밀값: 환경·파일에 `FAKE-TOKEN-…` → 결과 JSON·출력 줄에 그 문자열 0.
6. 클라이언트: 수집기 역할 출력에 `--bearer-token-env-var WORKMCP_MCP_TOKEN`과 `--transport http`가 있고 토큰 자리는 `<MCP_TOKEN>` 문자열; 로컬 역할 출력에 `-I -m workmcp serve`; `registered`가 가짜 `~/.claude.json`·`config.toml`에서 참/거짓/None.
7. `--dry-run`: 홈·파일 생성 0, 상태 `planned`.
8. `--upgrade`: 잠금 파일 있으면 exit 3; 백업 파일 생성·`integrity_check ok`; v5 스키마에서 "no migration needed".
9. 경계: `tests/test_network_boundary.py` 변경 없이 통과(`setup.py`가 `cli`를 import하면 순환 — `doctor`·`scan`·`index`는 `cli`가 아니라 **함수 인자로 주입**하거나 `setup.apply(..., commands=cli_functions)`로 받는다 **[결정]**: `cli.py`가 `setup.main(args, doctor=doctor, scan=scan, index=index_command)`로 넘김. `setup.py`의 허용 import는 `models`·`paths`·`config`·`store`·`sync`만 늘린다 — 네트워크 경계 테스트의 `MODULE_IMPORTS['setup.py']`를 그만큼 넓히는 것은 실행자 C가 **테스트 파일을 고치는 유일한 지점**이며 반영 기록에 적는다).

## 3. 오프라인 설치 묶음

피터 결정(2026-10-26 Q2): **주 경로는 공개 GitHub + PyPI + Hugging Face**, 묶음은 회사 프록시가 막을 때의 **예비 경로**. 완료 조건 ④는 예비 경로를 이 PC에서 재현하는 것이다.

### 3.1 구성 — **[결정]**

```
workmcp-bundle-0.0.1-<yyyymmdd>-<commit8>\          (코드 묶음, 약 60~100 MB [추정])
  README-BUNDLE.md        설치 5줄, 커밋 해시, SHA256SUMS 자체의 SHA-256(피터가 다른 경로로 대조)
  SHA256SUMS              아래 모든 파일의 sha256 (sha256sum 형식, 상대 경로)
  verify_bundle.py        tools/make_bundle.py 사본 (python -I verify_bundle.py . 로 전수 검증)
  requirements.lock.txt   저장소와 같은 파일 (pip --require-hashes 가 읽음)
  wheels\                 lock 51개의 win_amd64/py3-none-any 휠 + workmcp-0.0.1-py3-none-any.whl
  src.zip                 git archive <commit> (tests 포함 — 회사 PC 진단용 pytest; 선택 사용)
workmcp-model-bge-m3-5617a9f6\                       (모델 묶음, 2.28 GB, 매니페스트가 바뀔 때만 다시 만듦)
  model.onnx  model.onnx_data  Constant_7_attr__value  tokenizer.json    (평면 — models.import_from 이 읽는 형태)
  SHA256SUMS              models.MANIFEST 의 4개 해시와 같아야 함
python-3.12.x-amd64.exe                              (선택; python.org 사용자 설치기, 피터가 받아 넣음; 해시는 README-BUNDLE에)
```

- **휠만 설치**(`pip install --no-index --find-links wheels --require-hashes -r requirements.lock.txt` → `pip install --no-index --find-links wheels --no-deps workmcp==0.0.1`). 소스 설치가 없으므로 **`setuptools` 휠은 넣지 않는다**(M5 설계 §3.1의 "고정 setuptools"는 editable 설치용이었다 — 이 결정으로 불필요). `workmcp` 휠은 pip가 해시 검사를 하지 않으므로 `SHA256SUMS` 전수 검증이 그 자리를 맡는다.
- **Python 자체 — [결정] python.org 사용자 설치기(`InstallAllUsers=0`, 관리자 불필요)를 권하고 묶음 "밖 선택 요소"로 둔다.** 이유: ① 서명된 설치기라 회사 앱 제어·보안 소프트웨어에 걸릴 가능성이 가장 낮다 [추정] ② 설치 뒤 `py -3.12`·`venv`·`pip`이 모두 있다 ③ uv 관리 python-build-standalone 사본(68 MB)은 재배치는 될 것으로 보이나 **서명이 없다** [추정] — 회사 PC에서 막힐 위험이 크다. 회사 PC에 Python 3.12가 이미 있으면 그것을 쓴다(`py -0p`로 확인). 대안으로 standalone 사본을 `make_bundle.py --with-python <폴더>`로 넣을 수 있게 하되 기본은 끔(§10 Q3).
- **`src.zip`을 넣는 이유**: 회사 PC에서 `python -I -m pytest -q`로 같은 테스트를 진단으로 돌릴 수 있게(CLAUDE.md 의도, lock에 pytest가 든 이유). 설치에는 쓰지 않는다. 압축 해제 폴더를 데이터 홈으로 쓰지 않는다(README에 적음; `find_repo_root`가 `pyproject.toml` 조상을 찾으면 홈 규칙이 거부해 준다 **[사실]**).

### 3.2 생성 스크립트 `tools/make_bundle.py` (이 PC)

```
<PIP_PY> -I tools\make_bundle.py make --out D:\bundles [--model-from <모델 폴더>] [--with-python <폴더>] [--commit HEAD]
<PY>     -I tools\make_bundle.py verify <묶음 폴더>          # 회사 PC: SHA256SUMS 전수 검증 (같은 파일이 verify_bundle.py)
```

1. 전제 검사: `git status --porcelain` 비어 있음(아니면 exit 4), 커밋 해시 기록. `<PIP_PY>`는 **pip이 있는 3.12 Python**(이 PC 저장소 venv에는 pip이 없다 **[사실]** → `uv venv --seed <임시>`로 pip 있는 venv를 만들어 쓰거나 uv 관리 Python의 `python.exe -m ensurepip`). 스크립트는 `sys.executable -m pip --version`이 실패하면 이 힌트를 내고 exit 4.
2. 휠: `pip download --only-binary=:all: --require-hashes -r requirements.lock.txt -d wheels` — 이 PC가 대상과 같은 win_amd64·cp312라 플랫폼 인자 없이 받은 결과가 회사 PC와 같다 **[사실]**. `--require-hashes`가 lock의 해시와 **파일마다** 대조한다. 환경 마커로 `httpx2-jsfetch(emscripten)`은 빠지고 `pywin32`·`colorama`·`cffi`·`pycparser`는 들어온다. 개수 51(**[사실]** lock)인지 단언.
3. 프로젝트 휠: `pip wheel --no-deps -w wheels <repo>`(빌드 격리 켬 — 이 PC는 PyPI에서 `setuptools==84.2.1`을 받는다; 묶음에는 들어가지 않음).
4. `src.zip`: `git -c core.autocrlf=false archive --format=zip <commit> -o src.zip`(`.gitattributes`가 셸·유닛 파일을 LF로 고정 **[사실]**).
5. 모델(`--model-from`): 4파일을 1 MiB 블록으로 복사하며 SHA-256 대조. **스크립트는 `workmcp`를 import하지 않으므로**(tools 규칙) 해시 4개와 크기를 **파일 안 상수**로 둔다; `tests/test_tools_dir.py`(또는 새 `tests/test_bundle_tool.py`)가 `models.MANIFEST`와 같음을 단언.
6. `SHA256SUMS`(묶음별) → `README-BUNDLE.md`(커밋, 날짜, 파일 수, 바이트, `SHA256SUMS`의 SHA-256, 설치 5줄) → zip 2개(`zipfile`, ZIP64 자동 **[사실]** stdlib). 출력: `bundle: wheels 51+1 (xx MB), src.zip x MB -> workmcp-bundle-0.0.1-20261101-ce4dd5a.zip xx MB` / `model: 4 files 2,284,694,904 B -> workmcp-model-bge-m3-5617a9f6.zip`.
7. 묶음은 **저장소 밖**(`--out` 필수, 저장소 안이면 exit 4)에 만든다. `.gitignore`에 `*.whl`·`bundles/`를 더해 실수를 막는다(실행자 D).
8. `verify`: `SHA256SUMS`의 모든 줄을 다시 계산해 `ok N / mismatch M / missing K`를 내고 M+K가 0이면 exit 0. 2.28 GB 모델은 약 10~20초 [추정].

### 3.3 무결성 확인 방법(회사 PC)

① `verify_bundle.py` 전수 검증(exit 0) ② 피터가 이 PC에서 본 `SHA256SUMS`의 SHA-256(README-BUNDLE에 적힌 값)을 회사 PC에서 `certutil -hashfile SHA256SUMS SHA256`으로 대조 — 묶음 전체의 변조·손상을 한 값으로 잡는다 ③ pip `--require-hashes`가 설치 때 다시 대조 ④ 모델은 `fetch-model --from`/`setup --model-from`이 복사 중 대조하고 `verify-model`이 또 본다. 묶음 안 python-build-standalone·python.org 설치기의 상류 서명은 재검증하지 않는다(한계; 피터 자신이 만든 묶음이라는 사실이 신뢰 근거).

- 모델: 바뀌지 않음.

## 6. 합성 수집기 retire·시험 지식 정리

서버에 남은 것 **[사실]**: 수집기 `devpc-synthetic`(문서 52: 합성 51 + 원격 확인용 1), 개체 1(`org` "합성 거래처 A (원격 확인)"), 사실 1(견적 1,234,000원 — 근거 `long_line.txt`). 회사 자료가 올라간 뒤 검색에 합성 조각이 섞이면 안 되므로 **검색에서 사라지게** 한다. 행을 지우는 명령은 없고 만들지 않는다(append-only; `collectors retire`는 "its data stays" **[사실]**).

### 6.1 절차(기존 명령만; 순서 중요)

| # | 어디 | 명령 | 결과 확인 |
|---|---|---|---|
| 1 | 이 PC 합성 홈 `%USERPROFILE%\Motive_work_synthetic` | 합성 문서 폴더(`config.toml` `[[sources]]`의 폴더)의 **파일을 모두 지운다**(합성 파일이다; 폴더는 남김 — 루트가 없으면 scan이 exit 4) → `scan` | `deleted 52`(또는 51+1), `seen 0` |
| 2 | 이 PC | `push --dry-run` → `push` → `push` | dry run `deleted 52`; 첫 push `documents 52 … events N`; 두 번째 `up to date`. 서버는 문서를 `deleted`로 바꾸고 `refresh_chunks`가 청크·FTS를 지운다 **[사실]** |
| 3 | 서버(피터 승인; 에이전트 SSH) | `wm collectors retire devpc-synthetic`(+ ④에서 쓴 `devpc-bundle`도) | `retired collector devpc-synthetic at …; push tokens revoked now: 1` |
| 4 | 서버 | `wm index --gc`(벡터 중 청크가 더 안 쓰는 것 삭제 **[사실]** `--gc` 도움말) | 요약 줄 `vectors …`; `doctor` `vectors 0` |
| 5 | Claude Code(원격) | `retract(assertion_id=1, reason="M5 원격 확인 시험 기록 정리")` | `status withdrawn`; `list_knowledge` 현재 사실 0 |
| 6 | 서버 | `wm verify --stored`; `wm doctor` | `binding ok (nothing verified)` 또는 units 0; `collectors 2 (retired 2)`, `last push … documents 52` |
| 7 | 클라이언트 | `search "가상 거래처 A 견적"` | `hits 0`, `delivered_sources []` |

- 개체 1은 남는다(`entities`에 철회 없음). 이름이 "원격 확인"이라 혼동 위험이 작다. 지우고 싶으면 `knowledge forget-entity ID` 명령이 필요(§10 Q5, 기본 "남김").
- 1번에서 `[[sources]]` 항목을 지우는 방법은 쓰지 않는다: `config.sync_roots`는 루트를 `enabled 0`으로 바꿀 뿐이고 **[사실]**, 그 아래 문서가 `deleted`로 바뀌지는 않는 것으로 보인다 **[추정]**(실행자 E가 합성 홈에서 먼저 확인; 바뀐다면 그 길이 더 간단하다).
- 되돌리기: 합성 폴더에 파일을 다시 생성해 `scan`·`push`하면 `restored`로 돌아온다(토큰은 새로 발급해야 함 — retire된 수집기는 토큰을 받지 못하므로 **이름을 바꿔** 새 수집기로).

### 6.2 정리 뒤 기대 출력(PLAN ⑤ 근거)


## 7. Codex 원격 MCP 연결

### 7.1 설정 형식 — **[사실]**(공식 문서 + 이 PC `codex-cli 0.160.0 mcp add --help`, 접근일 2026-10-29)

사용자 설정 `%USERPROFILE%\.codex\config.toml`:

```toml
[mcp_servers.workmcp]
url = "https://<VPS_HOST>/workmcp/mcp"
bearer_token_env_var = "WORKMCP_MCP_TOKEN"   # 값은 사용자 환경변수에; 파일에 토큰 없음
startup_timeout_sec = 30                     # 기본 10 s (문서); 서버는 model_preload로 바로 응답하지만 여유
tool_timeout_sec = 120                       # 기본 60 s (문서); 첫 의미 검색 여유
```

명령줄로 같은 것: `codex mcp add workmcp --url https://<VPS_HOST>/workmcp/mcp --bearer-token-env-var WORKMCP_MCP_TOKEN`(timeout 두 키는 파일에 손으로). 출처: https://learn.chatgpt.com/docs/extend/mcp?surface=cli (키 `url`·`bearer_token_env_var`·`http_headers`·`env_http_headers`, `codex mcp login`은 OAuth 서버용 — 우리는 Bearer라 쓰지 않음), https://learn.chatgpt.com/docs/config-file/config-reference (`startup_timeout_sec` 기본 10 s, `tool_timeout_sec` 기본 60 s, `enabled`, `enabled_tools`; 프로젝트 `.codex/config.toml`은 신뢰한 프로젝트만). 두 URL 모두 `developers.openai.com/codex/...`에서 308로 옮겨진 주소다.

- 프로젝트 범위(`.codex/config.toml`)는 신뢰 승인이 필요하고 저장소 폴더에서만 보인다 → **사용자 범위를 기본**(피터 결정 2026-10-26 ③과 일치).
- `env_http_headers = { "Authorization" = "WORKMCP_MCP_TOKEN" }`은 값이 `Bearer ` 접두사를 못 붙이므로 쓰지 않는다 **[추정]** — `bearer_token_env_var`가 바른 키.
