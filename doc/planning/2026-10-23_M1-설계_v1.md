## 2. 수집 대상 설정·경로 규칙

### 2.1 `config.toml` (기준) — `<home>/config.toml`

```toml
# 모두 선택. 없으면 기본값. 비밀값 금지(.env만).
[scan]
max_file_mb = 100          # 초과: 해시만 계산, parse_status='too_large'
max_units = 200000         # 버전 하나의 단위 수 상한
max_text_chars = 50000000  # 버전 하나의 단위 텍스트 합계 상한
exclude = ["*.bak"]        # 기본 제외 패턴(§2.4)에 더함. fnmatch, 파일 이름에 적용
commit_every = 200
read_cloud_placeholders = false   # OneDrive Files On-Demand 자리표시자 읽기(=내려받기 유발) 금지

[[sources]]
path = 'D:\work\docs'      # 절대 경로. 합성 예시
exclude = ["drafts/*"]     # 루트 상대 경로에 적용(fnmatch, '/' 구분)
allow_network = false      # UNC·매핑 드라이브 허용 여부(§2.3)
```

- **[결정]** 기준은 파일이다. 이유: 사용자가 메모장으로 고칠 수 있고, stdlib에는 TOML **쓰기**가 없어 `sources add`를 만들면 직접 TOML 작성기가 필요하다. `source_roots` 표는 **거울**이다: `scan` 시작 시 설정의 루트를 `path_key`로 찾아 없으면 INSERT, 설정에서 빠진 루트는 `enabled=0`(행 삭제 없음 — `documents.root_id`가 가리킴). `scan --root P`로 준 루트도 같은 방식으로 표에 들어간다(`enabled`는 바꾸지 않음).
- **[결정]** `source_roots`에 열 추가 없음. 제외 패턴·허용 플래그는 설정 파일에만 있고 표는 경로·활성·추가 시각만 가진다.
- **[결정]** 설정 파일이 없고 `--root`도 없으면 `scan`은 종료 코드 4, stderr "no sources configured: write <home>\config.toml [[sources]] or pass --root".
- **[결정]** `Limits` 데이터클래스(`parsers/__init__.py`)가 `[scan]` 값을 받는다. 형식별 상한(§5.3)도 여기에 필드로 두되 설정 파일에는 노출하지 않는다(테스트가 작은 값을 주입하기 위한 것).

### 2.2 `source_roots` 거울 동기화 SQL(의사)

```
for root in roots:
    key = normcase(str(root.path))            # 이미 resolve된 경로
    row = SELECT id FROM source_roots WHERE path = key
    if row is None: INSERT INTO source_roots(path, enabled, added_at) VALUES(key, 1, now)
    elif from_config: UPDATE source_roots SET enabled=1 WHERE id=row.id
if from_config: UPDATE source_roots SET enabled=0 WHERE path NOT IN (keys)
```

### 2.3 수집 대상 경로 검증 (`config.validate_root(raw, home, repo_root, allow_network) -> Path`)

데이터 홈 규칙(M0 §2.2)과 **다른 규칙**이다. 홈은 "우리가 쓰는 곳"이라 동기화 폴더를 금지했지만, 원본은 피터의 자료라 어디든 읽을 수 있다 — 단 아래는 막는다. 순서대로 검사하고 `SourceRootError(code, message)`를 낸다.

| 순서 | 코드 | 규칙 | 판정 |
|---|---|---|---|
| 1 | `source_root_relative` | 절대 경로만 | `Path(raw).is_absolute()` 거짓(`\\?\X:\` 접두는 `paths._strip_long_prefix`로 벗김) |
| 2 | `source_root_trailing_dot_space` | 끝 공백·점 구성요소 금지 | `paths._trailing_dot_space` 재사용 |
| 3 | `source_root_missing` | 존재하는 폴더만 | `Path.is_dir()` 거짓(파일·없음·권한 없음) |
| 4 | `source_root_network` | UNC·매핑 드라이브 | `resolved = Path(raw).resolve()`; `paths._is_unc(str(raw))` 또는 `_is_unc(str(resolved))`이면 네트워크. **[추정]** 매핑 드라이브는 Python 3.12 `realpath`가 UNC로 풂(M0 §2.2 #5와 같은 가정, 이 PC에 매핑 드라이브가 없어 실측 못 함 — 실행자가 `subst`가 아닌 `net use`로 확인 가능하면 테스트에 `skipif`로). `allow_network=True`면 통과시키고 **경고 문자열**을 돌려준다(scan·doctor가 stderr에 출력) |
| 5 | `source_root_inside_home` | 데이터 홈 안·홈과 같음 | `paths._within(resolved, home)` |
| 6 | `source_root_contains_home` | 홈이 루트 안 | `paths._within(home, resolved)` — 우리 DB·로그를 색인하게 됨 |
| 7 | `source_root_inside_repo` | 저장소 안 | `repo_root`가 있으면 `_within(resolved, repo)` 또는 `_within(repo, resolved)`. 테스트는 항상 `tmp_path` 아래 루트를 쓰므로 걸리지 않음 |
| 8 | `source_roots_overlap` | 루트끼리 포함 관계 금지 | 설정 전체에 대해 쌍별 `_within` — 같은 문서가 두 루트에 속하는 것을 막음(`documents.path_key UNIQUE`와 `root_id` 모호성) |
| — | (코드 없음, 경고만) | 루트가 동기화 폴더 안 | `paths._sync_component(resolved)` 또는 OneDrive 환경변수 안이면 경고 "원본은 회사 동기화 정책에 따름, 우리 저장소는 로컬"(M0 §2.2 글머리·§10 질문). 거부하지 않음 |

- **[결정]** `_is_unc`·`_within`·`_trailing_dot_space`·`_strip_long_prefix`·`_sync_component`는 `paths.py`의 기존 함수를 **그대로 쓴다**(상대 import). `paths.py`는 그대로이고 `config.py`가 조합한다.
- **[결정]** 왜 네트워크 기본 거부인가: SMB로 읽으면 파일 이름·내용 요청이 파일 서버로 나간다. 서버(MCP)의 외부 호출 0 규칙은 "AI/API"에 대한 것이고 사내 파일 서버 읽기는 피터가 선택할 문제지만, 커널 SMB는 Python audit hook에 소켓 이벤트로 **보이지 않으므로**(**[사실]** 소켓 호출이 Python 층에서 일어나지 않음) 경계 테스트가 못 잡는다. 그래서 경로 규칙으로 막고 명시적 opt-in만 허용한다. 회사 파일 서버 연결 여부는 M5(§14).

## 3. 증분 감지

### 3.1 상태와 전이

파일 하나에 대한 결과 분류(모두 `scans.counts_json`에 세어 CLI 요약에 나옴):

| 결과 | 조건 | DB 변화 |
|---|---|---|
| `added` | `path_key`가 없음 | `documents` INSERT(`active`) + `versions` seq=1 + 단위 |
| `unchanged` | 최신 버전과 `(size, mtime_ns)` 같음 | `documents.last_seen_at`만 갱신(배치) |
| `touched` | size·mtime 다르지만 sha256이 최신 버전과 같음 | 최신 `versions.mtime_ns`(와 `size`는 같을 수밖에 없음) 갱신 — 버전 추가 없음 |
| `changed` | sha256 다름 | 옛 최신 `superseded_at=now`; 새 `versions` seq+1; 단위는 재사용 또는 파싱 |
| `restored` | `documents.status='deleted'`였는데 다시 보임 | `status='active', deleted_at=NULL`; **항상** 새 버전 seq+1(해시가 같아도; 단위 재사용) |
| `deleted` | 스캔 범위 안 `active` 문서가 이번에 안 보임 | `status='deleted', deleted_at=now`. 버전·단위 보존 |
| `unstable` | 읽기 전후 `stat`가 다름 | 없음(`last_seen_at`만 갱신), 다음 스캔 재시도 |
| `locked` | `open`/read에서 `PermissionError`·`OSError(errno 13, 32)` | 문서 행이 없으면 INSERT + 버전 `parse_status='locked'`(sha256은 **빈 문자열 불가** → `'0'*64`로 두고 `size`·`mtime_ns`는 stat 값; 재시도 때 교체). 이미 버전이 있으면 변화 없음 |
| `too_large` | `size > max_file_bytes` | 버전 행(스트리밍 해시 `hashlib.file_digest`), 단위 0 |
| `failed`/`unsupported`/`encrypted` | 파서 결과 | 버전 행 + `parse_error` 코드, 단위 0 |
| `skipped` | §2.4 자리표시자 | `documents.status='skipped'` |

- **[결정]** `locked` 버전의 sha256 자리표시 `'0'*64`는 "해시 없음"의 약속값이다. 재사용 조회(§3.3)는 `parse_status='ok'`만 보므로 섞이지 않는다. 다음 스캔에서 읽기에 성공하면 그 행의 `sha256·size·mtime_ns·parse_*`를 UPDATE한다(§10.2 트리거가 `sha256` 변경을 막으므로 **예외 규칙**: `OLD.parse_status='locked'`일 때만 `sha256` 변경 허용 — 트리거 WHEN 절에 포함).
- **[결정]** 재시도 정책: `locked`·`pending`은 매 스캔 재시도. `failed`는 `--retry-failed`를 줬을 때만(매번 재시도하면 손상 파일 하나가 스캔마다 비용). `too_large`·`unsupported`·`encrypted`는 내용이 바뀔 때만 자연 재시도. 파서 버전이 바뀐 최신 버전은 `--reparse`를 줬을 때 그 자리에서 단위를 다시 만든다(§3.4).
- **[결정]** 같은 size·mtime으로 내용만 바뀐 파일(mtime을 보존하는 복사 도구)은 1차에서 걸러져 **감지되지 않는다**. `scan --rehash`가 전 파일을 2차로 보낸다. 한계로 §13에 적음.

### 3.2 파일 하나의 절차 (`collect.process_file`)

```
st0 = entry.stat(follow_symlinks=False)
doc = known.get(path_key)                      # 스캔 시작 때 루트 단위로 한 번 읽은 dict
if doc and doc.status != 'skipped' and doc.latest and (st0.st_size, st0.st_mtime_ns) == (latest.size, latest.mtime_ns):
    mark_seen(doc); return 'unchanged'
if st0.st_size > limits.max_file_bytes:
    sha = stream_sha256(path)                  # open(path,'rb') + hashlib.file_digest
    data = None
else:
    data, sha, st1 = read_source(path)         # 아래
    if (st1.st_size, st1.st_mtime_ns) != (st0.st_size, st0.st_mtime_ns): mark_seen(doc); return 'unstable'
...버전 결정(§3.1 표) → 단위: reuse(sha, parser_version) or parse(data, ext, limits)
```

`collect.read_source(path) -> (bytes, sha256_hex, stat_after)`: 모듈 안에서 원본을 여는 **유일한 함수**. `with open(path, 'rb') as f: data = f.read()`; 그 뒤 `os.stat(path)`. `PermissionError`/`OSError(errno in (13, 32))`는 `SourceLocked`로 바꿔 던진다. 100 MiB까지 메모리에 올린다(**[결정]** 단순성 우선; 회사 PC 메모리에서 문제없는 크기).

### 3.3 같은 sha256 재출현 시 단위 재사용 절차 (M0 부록 B)

```sql
-- 후보: 같은 내용, 같은 파서 버전, 정상 파싱. 문서가 달라도 된다(복사본·이동).
SELECT id FROM versions
 WHERE sha256 = :sha AND parser_version = :current_parser_version AND parse_status = 'ok'
 ORDER BY id DESC LIMIT 1;
-- 있으면 (같은 트랜잭션 안에서)
INSERT INTO versions(document_id, seq, sha256, size, mtime_ns, observed_at, parser, parser_version, encoding,
                     parse_status, parse_error, unit_count, text_chars)
  SELECT :doc, :seq, sha256, :size, :mtime_ns, :now, parser, parser_version, encoding, 'ok', NULL, unit_count, text_chars
    FROM versions WHERE id = :src;
INSERT INTO units(version_id, ordinal, kind, locator_json, text, text_sha256)
  SELECT :new_id, ordinal, kind, locator_json, text, text_sha256 FROM units WHERE version_id = :src ORDER BY ordinal;
```

- 단위의 `locator_json`은 **단위 좌표만**(M0 §3.3 "unit 부분")이라 경로·문서 id를 담지 않으므로 다른 문서로 복사해도 옳다. 전체 locator는 응답 시 `documents.path`·`versions.sha256`을 붙여 만든다.
- 색인: `CREATE INDEX versions_by_sha256 ON versions(sha256, parser_version)`(§10.2). 기존 `versions_sha256(document_id, sha256)`은 유지.
- M2의 청크·벡터 재사용도 같은 후보 버전에서 `chunks`를 복사하고 `chunk_vectors`는 `text_sha256`으로 찾는다(M0 §5) — M1은 `units`까지만.
- `parser_version`이 다르면 재사용하지 않고 파싱한다(옛 파서가 만든 단위를 새 파서 이름으로 적을 수 없음).

### 3.4 삭제·이동·재파싱

- **삭제 판정**: 스캔 시작 시각 `started_at`을 기억하고, 걷기가 **정상 종료**된 뒤 `UPDATE documents SET status='deleted', deleted_at=:now WHERE root_id IN (:scanned_roots) AND status IN ('active','skipped') AND last_seen_at < :started_at`. 걷기가 예외·중단으로 끝나면 삭제 판정을 하지 않는다(`scans.status='aborted'`). `locked`·`unstable`·`skipped`도 `last_seen_at`을 갱신하므로 거짓 삭제가 없다.
- **부분 스캔**(`--root` 일부): 그 루트의 `root_id`만 삭제 판정. `scans.partial=1`.
- **이동·이름 변경**: 추적하지 않는다. 새 경로 = `added`(sha256 재사용으로 재파싱 없음), 옛 경로 = `deleted`. `recent_changes`(M3)가 "삭제+추가"로 보이는 것은 한계로 적고, **[제안]** M3에서 같은 sha256의 삭제·추가 쌍을 표시만 묶는다.
- **재파싱**(`--reparse`): 최신 버전의 `parser_version`이 현재 파서와 다르면 `DELETE FROM chunk_vectors…; DELETE FROM chunks WHERE version_id=?; DELETE FROM units WHERE version_id=?` 뒤 다시 파싱해 INSERT, `versions.parser_version·unit_count·text_chars` 갱신. `evidence`는 append-only라 남고, 그 locator가 더 이상 맞지 않으면 `verify`가 실패로 보인다 — 이것이 의도한 동작이다(근거가 재도출되지 않음을 숨기지 않음). **[주의]** M2 이후 `evidence.chunk_id`가 가리키는 청크는 FK 때문에 지울 수 없다 — M2 설계에서 "청크 보존 + 새 chunk_version" 또는 `chunk_id` 참조 해제를 정한다(부록 A).

### 3.5 트랜잭션·커밋·재개·잠금

- **[결정]** 연결은 `store.open_home`(autocommit, `isolation_level=None`). 수집기는 `BEGIN IMMEDIATE`로 배치를 열고 파일 `commit_every`(기본 200)개마다 `COMMIT`한다. 한 파일의 문서·버전·단위 INSERT는 **같은 배치**에 있으므로 중단 시 "버전은 있는데 단위가 없는" 상태가 생기지 않는다.
- **재개**: 다음 스캔은 1차 비교로 이미 기록된 파일을 건너뛴다. 별도 체크포인트 없음.
- **`scans` 행**: 시작 시 `status='running'` INSERT(별도 짧은 트랜잭션으로 즉시 COMMIT). 정상 끝 `done`, 예외 `aborted`(카운트까지 적음). 시작 시 `running` 행이 남아 있으면 `aborted`로 고치고 로그에 적는다.
- **`scan.lock`**(`store.acquire_scan_lock(home)`): `os.open(path, O_CREAT|O_EXCL|O_WRONLY)`로 만들고 `{"pid", "started_at"}` JSON을 쓴다. 이미 있으면 내용의 `started_at`이 24시간 이전이면 **오래된 잠금**으로 보고 지우고 다시 시도(로그·stderr 경고), 아니면 종료 코드 3 "another scan is running (pid …, since …); if not, delete <path>". `os.kill(pid, 0)`로 생존 확인은 **하지 않는다**(**[사실]** Windows에서 `os.kill`은 신호 0도 `TerminateProcess`를 부른다 — Python 문서). 정상·예외 종료 모두 `finally`에서 잠금 파일을 지운다.

## 4. 원본 읽기 전용 보장

### 4.1 코드 규칙

1. 원본 파일을 여는 곳은 `collect.read_source`(전체 읽기)와 `collect.stream_sha256`(too_large) **두 함수만**. 둘 다 `open(path, 'rb')`.
2. 파서는 `bytes`를 받는다. pypdf는 `PdfReader(io.BytesIO(data))`, olefile은 `olefile.OleFileIO(io.BytesIO(data))`, zipfile은 `zipfile.ZipFile(io.BytesIO(data))`. 서드파티·stdlib 컨테이너 라이브러리가 **경로를 보지 않으므로** 쓰기 모드로 열 가능성 자체가 없다. 압축 해제는 메모리에서만(임시 파일 없음).
3. `collect.py`·`binding.py`·`parsers/*`에서 금지: `os.open`(잠금은 `store.py`), `open`의 `'rb'` 외 모드, `Path.write_*/touch/unlink/rename/replace/rmdir/mkdir/chmod`, `os.remove/unlink/rename/replace/utime/chmod/truncate/mkdir/makedirs/rmdir/link/symlink`, `shutil`·`tempfile` 전체(허용 목록에 없으므로 import 자체가 위반).
4. 해시·파싱은 같은 `bytes`에서 하므로 "해시한 파일과 파싱한 파일이 다른" 경우가 없다.

### 4.2 정적 테스트 (`tests/test_readonly.py::test_collector_and_parsers_have_no_write_api`)

대상 `src/workmcp/collect.py`, `binding.py`, `parsers/*.py`. AST로:
- `open(...)`, `io.open(...)`, `*.open(...)` 호출: 두 번째 위치 인자 또는 `mode=`가 **상수 `'rb'`**가 아니면 위반(인자 없음도 위반 — 기본 `'r'` 텍스트 모드 금지). `zipfile.ZipFile(...).open(name)`은 zip 내부 멤버 읽기라서 예외로 두고 싶지만 정적으로 구분하기 어렵다 → **[결정]** `_container.py`에서 멤버 읽기는 `z.open(name)` 대신 `z.open(name, 'r')`로 모드를 명시하고, 검사 규칙은 "`.open` 호출은 모드 상수가 `'rb'` 또는 (`_container.py`에서만) `'r'`"로 둔다.
- 속성·이름 금지 집합 `{'write_text','write_bytes','touch','unlink','rename','rmdir','mkdir','makedirs','removedirs','chmod','utime','truncate','link','symlink','copyfile','copy2','copytree','move','rmtree','mkstemp','mkdtemp','NamedTemporaryFile','TemporaryFile','write'}` — 어떤 수신자든 위반. `qualify()`로 `os.remove`·`os.replace`·`os.open` 위반(`str.replace`·`list.remove`는 수신자가 `os`가 아니므로 통과 — 정적 검사의 구멍은 4.3 런타임이 메운다).
- 양성 대조군 snippet 8개(`open(p)`, `open(p,'r')`, `open(p,'rb+')`, `Path(p).write_bytes(b'')`, `os.remove(p)`, `os.replace(a,b)`, `os.open(p, os.O_RDONLY)`, `import shutil`)가 모두 위반으로 잡힘.

### 4.3 런타임 테스트 (`tests/_audited_server.py scan` 모드 + `tests/test_readonly.py`)

- **[사실]**(이 PC 실측) `sys.addaudithook` `open` 이벤트의 인자는 `(path, mode, flags)`이고, Python 층에서 `'rb'`로 열어도 mode는 **`'r'`**로 온다(`FileIO`가 `b`를 떼기 때문). `'w'`→`('w', 33665)`, `'r+b'`→`('r+', 32898)`, `'ab'`→`('a', 33161)`, `os.open(p, O_RDONLY)`→`(None, 128)`, `os.open(p, O_WRONLY|O_APPEND)`→`(None, 137)`. `Path.touch()`·`os.utime`→`os.utime`, `Path.write_bytes`→`open 'w'`, `shutil.copyfile`→`shutil.copyfile` + `open 'r'`/`'w'`, `os.replace`→`os.rename`, `os.remove`→`os.remove`, `os.chmod`→`os.chmod`. `zipfile.ZipFile(path)`는 `open 'r'`. `sqlite3`는 `open` 이벤트를 내지 않는다(C 층).
- **판정 함수** `judge_source_write(event, args, root) -> str | None`(`_audited_server.py`에 추가, 순수 함수라 단위 테스트 가능):
  - `open`: `args[0]`이 `root` 아래(normcase 접두 비교)이고 (mode에 `w`·`a`·`x`·`+` 중 하나 포함) 또는 (mode가 None이고 `flags & (O_WRONLY|O_RDWR|O_APPEND|O_CREAT|O_TRUNC) != 0`, 값 1·2·8·256·512)이면 위반.
  - `os.remove`, `os.unlink`, `os.rename`, `os.rmdir`, `os.mkdir`, `os.utime`, `os.chmod`, `os.truncate`, `os.link`, `os.symlink`, `shutil.*`: 인자 중 문자열/`PathLike`가 `root` 아래면 위반.
  - 그 밖은 None. 네트워크·프로세스 판정(`judge`)은 그대로 함께 적용.
- **`scan` 모드**: `python tests/_audited_server.py LOG scan <ROOT>` — hook 설치 후 `config.validate_root`→`collect.scan(home, [root])`→`binding.verify(...)`→두 번째 `collect.scan`(증분, 전부 `unchanged`가 나와야 함)을 돌리고 결과·이벤트를 LOG에 쓴다. 테스트(`test_scan_and_verify_never_write_to_sources`)는 (a) 묶음을 `tmp_path/'src'`에 생성 → (b) 전 파일 `(size, mtime_ns, sha256, st_file_attributes)`와 디렉터리 목록을 기록 → (c) 래퍼 실행, 종료 코드 0 → (d) 위반 이벤트 0건, `root` 아래 `open` 이벤트가 **1건 이상** 있고(검사가 실제로 봤다는 양성 확인) 모두 mode `'r'`·쓰기 플래그 0 → (e) 다시 기록해 (b)와 글자 단위로 같음(새 파일·사라진 파일·속성 변화 없음) → (f) 네트워크·프로세스 위반 0건.
- **양성 대조군**(`test_source_write_judge_flags_every_write_form`): 위 실측 이벤트 튜플 10개(`'w'`, `'a'`, `'r+'`, `None,137`, `None,256+1`, `os.utime`, `os.remove`, `os.rename`, `os.chmod`, `shutil.copyfile`)는 위반, `'r'`·`None,128`·루트 밖 경로는 통과. 그리고 `probe` 모드에 "루트 아래 `Path.write_bytes` 시도"를 더해 실제 hook이 기록·차단함을 확인(기존 `probe`처럼 `PermissionError`로 막음).
- **[제안]** 추가 안전띠: 테스트가 묶음 생성 뒤 전 파일에 읽기 전용 속성(`os.chmod(p, 0o444)`)을 켜고 스캔하면 어떤 쓰기도 OS 수준에서 실패한다. 비용이 없으니 `test_scan_and_verify_never_write_to_sources`에 넣는다(정리 때 되돌림).

### 5.1 공유 인터페이스 (`parsers/__init__.py`, A가 0단계에서 고정)

```python
@dataclass(frozen=True)
class Unit:
    ordinal: int          # 1-based, 문서 순서
    kind: str             # locator.UNIT_KINDS 키
    unit: dict            # locator 'unit' 부분(kind 포함). 저장 시 json.dumps(sort_keys=True, ensure_ascii=False)
    text: str             # 비어 있지 않음(strip 후). 정규화는 각 절의 규칙만

@dataclass(frozen=True)
class Limits:             # 기본값은 §5.3 표. config.[scan]과 테스트가 덧씌움
    max_file_bytes: int = 100 * 2**20
    max_units: int = 200_000
    max_text_chars: int = 50_000_000
    csv_max_columns: int = 1_000
    pdf_max_pages: int = 2_000
    pptx_max_slides: int = 2_000
    xlsx_max_sheets: int = 1_000
    eml_max_parts: int = 1_000
    hwp_max_sections: int = 1_000
    zip_max_entries: int = 10_000
    zip_max_part_bytes: int = 128 * 2**20
    zip_max_total_bytes: int = 512 * 2**20
    # §15.1 XML 구조 상한
    xml_max_depth: int = 256
    xml_max_attributes: int = 1_000
    xml_max_markup_bytes: int = 2**20
    xml_max_names: int = 10_000
    # §15.2 파일 하나의 예산(파서 자원 설계 §2.3)
    max_unit_chars: int = 8 * 2**20        # 단위 하나·XML 텍스트 노드 하나 (옛 xml_max_text_chars)
    hwp_max_para_bytes: int = 16 * 2**20
    max_events: int = 30_000_000          # 검토 v4 M1-L20: 50,000,000에서 내림
    max_held_bytes: int = 256 * 2**20     # 검토 v4 M1-10: 128 MiB에서 올림, 공유 문자열은 실제 크기
    parse_seconds: float = 60.0

class ParseFailure(Exception):
    def __init__(self, status: str, code: str):   # status ∈ {'failed','unsupported','too_large','encrypted'}
        ...

@dataclass(frozen=True)
class ParseResult:
    parser: str            # 'text'|'csv'|'pdf'|'docx'|'pptx'|'xlsx'|'eml'|'hwp'|'hwpx'
    parser_version: str    # §5.5
    encoding: str | None
    status: str            # versions.parse_status 값
    error: str | None      # parse_error 코드(§5.6), status='ok'면 None
    units: tuple[Unit, ...]

def parse(data: bytes, ext: str, limits: Limits) -> ParseResult   # 예외를 던지지 않음(모두 status로)
def parser_for(ext: str) -> Parser                                  # name, version, parse(data, limits, budget)
```

- **[결정]** 각 파서 모듈은 `NAME: str`, `VERSION: str`, `parse(data: bytes, limits: Limits, budget: _container.Budget) -> tuple[list[Unit], str | None]`을 노출하고 `ParseFailure`만 던진다(§15.2: `budget`은 디스패처가 파일마다 하나 만든다). 그 밖의 예외는 디스패처가 `('failed', 'exception:<ClassName>')`로 바꾼다 — **라이브러리 예외 메시지는 저장·로그하지 않는다**(문서 본문이 섞일 수 있음).
- **[결정]** 디스패처가 하는 일: 확장자 분기 → 매직바이트 판별(§5.2) → 파일 예산 `Budget(limits)` 생성 → 모듈 `parse(data, limits, budget)` → `ordinal` 연속 1..N 재부여·`locator.check_unit(unit)` 통과 확인(실패 시 `failed/unit_shape_invalid` — 파서 버그를 DB에 넣지 않음)·locator 중복은 digest로 확인(`unit_duplicate`) — 이 후처리도 같은 예산의 시계 안(1,024단위마다) → `len(units) > max_units` 또는 텍스트 합 `> max_text_chars`면 `too_large`(`limit_units`/`limit_chars`, 파서가 이미 예산에 차감하므로 2차 방어) → `ParseResult`.
- **[결정]** 결정성: 같은 bytes·같은 `Limits`·같은 파서 버전이면 결과가 바이트 단위로 같아야 한다(결속의 전제). dict 순서 의존·현재 시각·난수·환경 로케일 사용 금지. 테스트 `test_parsers_are_deterministic`가 형식마다 두 번 파싱해 비교한다.
- **[결정]** 텍스트 정규화 최소: 단위 텍스트는 추출된 그대로에서 **앞뒤 공백만 `strip()`**, 빈 단위는 버림. 내부 공백·줄바꿈 유지(검색 품질용 정규화는 M2 청크 단계의 일). 단, 줄 단위 파서는 줄 끝 `\r`을 뗀다(§5.7).

### 5.4 XML 파싱 안전성 (stdlib로 충분한 이유와 대책)

- **[사실]**(이 PC 실측) venv Python 3.12.13의 expat은 **2.7.4**. `xml.etree.ElementTree.fromstring`은 외부 엔터티(`<!ENTITY e SYSTEM "file:///…">`)를 **가져오지 않고** `ParseError: undefined entity`를 낸다. 내부 엔터티 중첩(billion laughs 축소판)은 확장되지만 expat ≥ 2.4.1의 증폭 방어가 기본으로 켜져 있다(확장 비율 상한).
- **[결정]** 대책 세 겹: (1) XML 부분을 파싱하기 **전에 바이트 검사**로 `b'<!DOCTYPE'` 또는 `b'<!ENTITY'`가 있으면 `failed/xml_dtd` — OOXML·HWPX 정상 문서에는 DTD가 없다. (2) 멤버 크기 경계 읽기(§5.3)로 메모리 상한. (3) 테스트 `test_expat_has_amplification_protection`: `pyexpat.version_info >= (2, 4, 1)` 단언(회사 PC Python이 달라질 때 조기 경보). `defusedxml`은 (1) 때문에 불필요하다. XLSX 시트·sharedStrings는 `ET.iterparse(io.BytesIO(part))`로 요소를 처리 후 `clear()`해 큰 시트도 메모리를 제한한다; DOCX·PPTX·HWPX는 `ET.fromstring`.
- zip bomb: §5.3의 세 상한 + 중첩 zip은 읽지 않음(M0 §6 #16 "ZIP 재귀 버림").

### 5.5 파서 버전 문자열

형식 `"<name>-<n>"`, 서드파티 라이브러리가 출력을 결정하면 `"/<lib>-<ver>"`를 붙인다(`importlib.metadata.version`). 라이브러리가 바뀌면 다른 버전이 되어 재사용·결속에서 자동으로 구분된다.

| 파서 | `parser` | `parser_version` 초기값 |
|---|---|---|
| TXT·MD | `text` | `text-1` |
| CSV | `csv` | `csv-1` |
| PDF | `pdf` | `pdf-1/pypdf-6.10.0` |
| DOCX | `docx` | `docx-1` |
| PPTX | `pptx` | `pptx-1` |
| XLSX | `xlsx` | `xlsx-1` |
| EML | `eml` | `eml-1` |
| HWP | `hwp` | `hwp-1/olefile-<ver>` |
| HWPX | `hwpx` | `hwpx-1` |

규칙: 단위 분할·텍스트 규칙이 바뀌면 `n`을 올린다(결과가 같아도 올리면 재파싱이 늘 뿐 안전). 거부 경계가 바뀌어도 올린다(`verify`가 옛 ok 버전을 새 상한으로 다시 파싱해 `too_large`가 나오면 실패가 아니라 `parser_version_mismatch`로 격리되도록).

현재 값(§15.2 파서 자원 설계 반영, 검토 v4 반영으로 다시 상향): `text-3`, `csv-3`, `pdf-4/pypdf-6.10.0`, `docx-5`, `pptx-5`, `xlsx-5`, `eml-4`, `hwp-5/olefile-0.47`, `hwpx-5`.

### 5.7 인코딩 사다리 (TXT·MD·CSV; `parsers/text.decode`)

1. `b'\x00'`이 있고 UTF-16 BOM(`FF FE`/`FE FF`)이 없으면 `failed/binary_content`.
2. `utf-8-sig`로 디코드 시도 → 성공: `encoding = 'utf-8-sig'`(BOM 있었음) 또는 `'utf-8'`.
3. UTF-16 BOM이 있으면 `utf-16` → `encoding='utf-16'`.
4. `cp949` → `encoding='cp949'`. (cp949는 잘못된 선두·후행 바이트에서 실패하므로 임의 바이너리를 잘 거른다 — 그래도 2·3을 먼저 한다.)
5. 모두 실패 → `failed/encoding_unknown`.

줄 나누기: `re.split(r'\r\n|\r|\n', text)` — **[결정]** `str.splitlines()`를 쓰지 않는다(`\x0b`·`\x0c`·`\x1c`~`\x1e`·`\x85`·U+2028/2029도 줄로 세어 편집기 줄 번호와 어긋남). 줄 번호는 1-based 원본 줄 번호(빈 줄도 번호를 차지하지만 단위는 만들지 않음). EML·XML 계열은 자체 인코딩 선언을 따르므로 사다리를 쓰지 않고 `encoding`은 `NULL`(EML은 `'rfc822'`).

## 6. 결속 검사 (`binding.py`)

### 6.1 범위 선언 (kakao `binding.SCOPE` 계승)

`SCOPE = '결속 100% = parse_status가 ok인 버전 중 현재 파일의 sha256이 그 버전과 같은 것 전부에 대해, 저장된 단위(순서·종류·좌표·텍스트·해시)·청크·근거 인용이 같은 파서 버전으로 현재 파일에서 다시 만들어진 값과 같음. 파서가 원문을 올바르게 읽었는지는 보이지 않음. 파일이 바뀐 옛 버전은 재검증 불가(stale)로 따로 셈.'`

### 6.2 버전 하나 (`binding.verify_version(db, version_id, cache) -> dict`)

1. `versions`·`documents` 행 읽기. `parse_status != 'ok'` → `{'result':'skipped_not_ok'}`.
2. `collect.read_source(path)`(같은 읽기 전용 경로). 파일 없음 → `missing`, 잠김 → `locked`, 읽기 전후 stat 다름 → `unstable`.
3. `sha256(data) != versions.sha256` → `stale`(최신 버전이면 `note='file changed since last scan; run scan'`).
4. `current = parsers.parser_for(ext).VERSION`; `versions.parser_version != current` → `parser_version_mismatch`(검증 불가; `scan --reparse` 안내).
5. `cache[(sha256, parser_version)]`가 없으면 `parsers.parse(data, ext, limits)`(A→B→A에서 두 A 버전은 한 번만 파싱). `status != 'ok'` → 실패 `reparse_failed:<code>`.
6. 단위 비교: 저장 `units`(ordinal 순)와 재도출 목록을 같은 길이·같은 `(ordinal, kind, locator_json, text)`로 비교, `text_sha256 == sha256(text)`도 확인. 차이마다 실패 항목 `{'version_id','ordinal','problem'}`(최대 20개, kakao `MAX_FAILURES`).
7. 청크(M2부터 존재): `chunks` 행마다 `'\n'.join(units[unit_first-1:unit_last].text)[char_start:char_end] == text`·해시 일치.
8. 근거: `evidence WHERE version_id=?` 행마다 `locator.check_shape` → 단위 찾기(`locator_json`의 `unit`과 같은 단위) → `locator.check_text(obj, unit.text) == quote` → `sha256(quote) == quote_sha256`.
9. 반환 `{'version_id','document_id','path','result': 'ok'|'failed'|'stale'|'missing'|'locked'|'unstable'|'parser_version_mismatch'|'skipped_not_ok', 'units_total','units_bound','chunks_checked','evidence_checked','failures':[...]}`.

### 6.3 집계 (`binding.verify(db, roots=None, document_ids=None, limits) -> dict`)

```
{
 'scope': SCOPE, 'parser_versions': {ext: current}, 'checked_at': iso,
 'versions': {'total': n, 'checked': k, 'ok': a, 'failed': b,
              'unverifiable': {'stale': .., 'missing': .., 'locked': .., 'unstable': .., 'parser_version_mismatch': .., 'skipped_not_ok': ..}},
 'units': {'total': .., 'bound': .., 'rate': bound/total(0.0 if total==0)},
 'chunks_checked': .., 'evidence_checked': ..,
 'ok': failed == 0,                       # 100%의 정의. 검증 불가는 ok를 깨지 않지만 보고에 드러남
 'failures': [...][:20]
}
```

- **[결정]** `ok`는 "검사한 것 중 실패 0". M1 완료 출력에서는 합성 묶음 직후라 `unverifiable`이 모두 0이어야 하고, 테스트는 `ok and unverifiable 합 == 0 and units.bound == units.total > 0`을 단언한다.
- **[결정]** 파일이 바뀐 경우: `stale`로 세고 실패로 치지 않는다. 그 문서의 최신 버전이 stale이면 `notice`에 "N개 문서가 마지막 스캔 이후 바뀜 — `workmcp scan`을 먼저 실행" 한 줄.
- `binding.validate_locator(db, obj) -> dict`(M0 부록 B 이탈 5): `locator.check_shape` → `versions WHERE id의 document_id=doc AND sha256=` 존재(`version_not_found`) → 그 버전의 단위 중 `locator_json`(`unit` 부분, `sort_keys` JSON)이 같은 행(`unit_not_found`) → `locator.check_text`. 반환 `{'version_id','unit_id','text'}`. M3 `get_snippet`·M4 쓰기 도구가 쓴다.

### 6.4 `cli verify` 출력

```
verify 2026-10-23T10:05:00+09:00  versions 14 checked 14 ok 14 failed 0  unverifiable 0 (stale 0, missing 0, locked 0, unstable 0, parser 0, not_ok 0)
units 348/348 bound (100.0%)  chunks 0  evidence 0
binding ok
```
실패 시 `binding FAILED` 뒤 실패 항목 최대 20줄(`<path> @ <sha12> / <unit_label> : <problem>` — 본문 텍스트는 찍지 않고 `problem`은 코드 문구만). 종료 코드 0/1. `--root`·`--doc ID`로 범위 축소.

## 7. 합성 문서 묶음

### 7.1 방식 결정

- **[결정] 테스트 시점 생성기, 커밋 바이너리 0개.** 이유: (1) 저장소에 회사 자료가 들어갈 통로를 원천 차단(생성기 소스는 사람이 읽어 합성임을 확인 가능, 검토자 체크리스트 M0 §9 #13) (2) diff로 변경 추적 (3) 경계 사례(손상·암호화·DTD·zip 상한)를 바이트 단위로 통제 (4) 상한 테스트는 작은 `Limits`로 하므로 거대 파일을 만들 필요 없음.
- **[사실]** Motive_vari 두 태그에 `.hwp`·`.hwpx`·`.docx`·`.xlsx`는 **없다**. `g0-freeze-20261017`에는 G0 평가 하네스의 합성 fixture가 대량 있다(`evals/fixtures/**`: eml 12,960·pptx 7,220·pdf 1,220·md·txt·csv; 생성기 `evals/build_manifest.py`는 `reportlab`(`UnicodeCIDFont('HYSMyeongJo-Medium')`로 한글 PDF)·`python-pptx`·`email.message.EmailMessage` 사용). 내용은 합성이지만 **재사용하지 않는다**: AGENTS.md가 G0 평가 하네스 복사를 금하고, reportlab·python-pptx를 끌어온다. 가져갈 것은 EML을 `EmailMessage`로 만든다는 **방식**과, PDF 한글은 CID 폰트+CMap으로 가능하다는 **사실**뿐이다. `kakao-p1` 태그의 fixture는 카톡 대화 텍스트라 무관.
- **[결정]** 생성기는 테스트 코드(`tests/`)이므로 패키지 허용 목록 대상이 아니다. stdlib만 쓴다(`zipfile`, `xml.etree`·문자열 템플릿, `email`, `struct`, `zlib`).

### 7.2 합성 내용 규칙 (`tests/fixtures/__init__.py`에 상수·docstring으로 고정)

- 실존 인물·회사·제품·주소·전화번호·이메일 **금지**. 사람은 "담당자 갑/을/병", 조직은 "가상 거래처 A", 프로젝트는 "합성 프로젝트 1호", 도메인은 `example.com`·`.invalid`(RFC 2606), 금액·날짜는 임의.
- 모든 문서에 공용 **표지 토큰** `SENTINEL = '합성표지7f3a'`를 한 번 이상 넣는다 → "로그·stdout에 본문 없음" 테스트가 이 토큰을 grep한다(§9).
- 한글·영문·숫자 혼합 문장 목록 `LINES_KO`·`LINES_EN`을 공용으로 두어 형식별 기대 단위를 계산 가능하게 한다.
- `Expected(rel_path, parser, status, error, unit_count, units_sample: dict[ordinal, (kind, unit, text)])`를 생성기가 돌려준다 — 파서 테스트와 묶음 테스트가 같은 기대값을 쓴다.

### 7.4 최소 CFB(OLE2) 작성기 (`tests/fixtures/cfb.py`, C)

`write_cfb(entries: dict[str, bytes | dict]) -> bytes`. 요구: olefile이 열 수 있는 유효 파일. 사양 요지(MS-CFB):
- 섹터 512B(`sector shift 9`), 미니 섹터 64B(`shift 6`), 미니 스트림 경계 4096B. 헤더 512B: 서명 `D0 CF 11 E0 A1 B1 1A E1`, minor 0x003E, major 3, byte order 0xFFFE, FAT 섹터 수, 디렉터리 시작 섹터, 미니 FAT 시작·개수, DIFAT 시작 `0xFFFFFFFE`·개수 0, 헤더 안 DIFAT 109칸(첫 칸 = FAT 섹터, 나머지 `0xFFFFFFFF`).
- **4096B 미만 스트림은 미니 스트림에**(올레는 크기로 판단해 미니 스트림에서 읽으므로 **필수** — 그렇지 않으면 olefile이 잘못 읽음). 루트 엔트리의 스트림이 미니 스트림 컨테이너.
- 디렉터리 엔트리 128B: 이름 UTF-16LE(끝 NUL 포함 길이), 타입(루트 5·스토리지 1·스트림 2), 색, 좌·우·자식 포인터, 시작 섹터, 크기. 트리는 "이름 길이 → 대문자 비교" 정렬의 단순 이진 트리로 충분(검정 색으로 통일; olefile은 색을 검증하지 않음).
- 테스트 `test_cfb_writer_roundtrips_through_olefile`: 쓴 스트림을 olefile로 다시 읽어 바이트 동일.
- **[제안]** 시간이 모자라면 1차로 모든 스트림을 4096B 이상으로 0 패딩해 일반 섹터에만 두는 단순판을 쓰고(우리 HWP 파서는 `decompressobj`가 꼬리 0을 허용하고 `FileHeader[36:40]`만 읽어 영향 없음), 미니 스트림판은 후속 커밋으로 — 다만 문서에 "실제 HWP와 구조가 다름"을 적는다.
- 재사용: 암호화 OOXML 사례(`EncryptionInfo`·`EncryptedPackage` 스트림), 옛 OLE 문서 사례(빈 `WordDocument` 스트림).

### 7.5 묶음 조립 (`tests/fixtures/bundle.py`, A)

`write_bundle(root: Path, *, with_edges=True) -> list[Expected]` — 하위 폴더 `docs/`, `mail/`, `sheets/`, `edge/`에 위 형식을 배치하고, 제외 규칙 확인용으로 `node_modules/x.txt`, `~$lock.docx`, 숨김 속성 파일, `.git/config`, 지원하지 않는 `image.png`를 넣는다. 묶음은 항상 `tmp_path` 아래(저장소 밖). 기대 합계(단위 수·상태별 건수)를 돌려주어 `scan` 요약과 비교한다.

### 10.1 v1 직접 수정 vs v2 추가 — **v1 수정**

- **[사실]** 스키마 v1은 커밋됐지만(`e8866e2`) 실제 데이터 홈은 만들어진 적이 없다(검토 v3 §1.4 `not created yet`; PLAN §5 M0 완료 근거). 테스트 DB만 존재.
- **[결정]** v1을 고친다(`SCHEMA_V1` 편집, `MIGRATIONS`는 한 항목 유지). 이유: (1) M0 검토 반영도 같은 규칙으로 v1을 고쳤다(M0 설계 §3.1·§11 "(스키마 v1) 반영") (2) 배포 전 스키마에 마이그레이션 사슬을 쌓으면 읽기 어렵고, 부분 적용 상태를 테스트해야 한다 (3) `migrate`의 체크섬 검사는 그대로 있어 **M5 첫 설치 이후**에는 v1이 동결되고 그 뒤 변경은 v2+로만 한다 — 이 동결 시점을 `store.py` 주석과 PLAN §5 M5 완료 근거에 적는다. 부작용: 개발 PC에 M0 실험용 DB가 있다면 `checksum changed`로 열기를 거부한다 → `doctor`가 그 오류를 "개발 중 스키마 변경: `<home>\db\work.sqlite3`를 지우고 다시 scan" 안내로 바꿔 출력(배포 전 한정 문구).
- 대안(v2 추가)을 택할 조건: 피터가 M1 중에 실제 자료로 scan을 돌려 보기 시작하면(PLAN §6 보류 항목이라 M5 전엔 없음).

### 10.2 변경 DDL (설명용; 기준은 코드)

```sql
-- documents: 건너뛴 이유
ALTER: documents(... , skip_reason TEXT)        -- v1 편집이므로 CREATE TABLE 안에 열 추가

-- versions: 재사용 조회(문서 무관)
CREATE INDEX versions_by_sha256 ON versions(sha256, parser_version);

-- versions 보호(검토 v3 §1.5 참고 지적, 부록 B): 관측 사실(document_id, seq, sha256, size, observed_at)은 불변,
-- superseded_at은 NULL→값 한 번, mtime_ns·파서 결과 열은 갱신 가능(touched·재시도·--reparse).
-- 예외: locked 자리표시(sha256='0'*64)는 읽기 성공 시 sha256·size를 채울 수 있다.
CREATE TRIGGER versions_update_guard BEFORE UPDATE ON versions
  WHEN NEW.id <> OLD.id OR NEW.document_id <> OLD.document_id OR NEW.seq <> OLD.seq
    OR NEW.observed_at <> OLD.observed_at
    OR ((NEW.sha256 <> OLD.sha256 OR NEW.size <> OLD.size) AND OLD.parse_status <> 'locked')
    OR (OLD.superseded_at IS NOT NULL AND NEW.superseded_at IS NOT OLD.superseded_at)
  BEGIN SELECT RAISE(ABORT, 'version identity is append-only'); END;
CREATE TRIGGER versions_no_delete BEFORE DELETE ON versions BEGIN SELECT RAISE(ABORT, 'append-only'); END;
CREATE TRIGGER versions_no_replace BEFORE INSERT ON versions
  WHEN EXISTS(SELECT 1 FROM versions WHERE id = NEW.id)
  BEGIN SELECT RAISE(ABORT, 'append-only'); END;
-- (UNIQUE(document_id, seq)가 있으므로 REPLACE가 그 키로도 옛 행을 지울 수 있다 → 같은 (document_id, seq) INSERT도 거부)
CREATE TRIGGER versions_no_replace_seq BEFORE INSERT ON versions
  WHEN EXISTS(SELECT 1 FROM versions WHERE document_id = NEW.document_id AND seq = NEW.seq)
  BEGIN SELECT RAISE(ABORT, 'append-only'); END;

-- 스캔 이력·요약 (status.last_scan, 재개 판단)
CREATE TABLE scans(id INTEGER PRIMARY KEY, started_at TEXT NOT NULL, finished_at TEXT,
  status TEXT NOT NULL CHECK(status IN ('running','done','aborted')),
  partial INTEGER NOT NULL DEFAULT 0, roots_json TEXT NOT NULL,
  counts_json TEXT NOT NULL DEFAULT '{}', note TEXT);
```

- `units`·`chunks`는 트리거 없음(재도출 가능한 파생이며 `--reparse`가 지운다). `documents`도 없음(`status`·`last_seen_at`을 자주 갱신).
- `tools.status.last_scan` = `SELECT finished_at, counts_json FROM scans WHERE status='done' ORDER BY id DESC LIMIT 1` → `{at, added, changed, deleted, failed}`; 없으면 `null`+기존 notice.
- 테스트(`test_store_schema.py` 추가): versions 트리거 거부 사례(`sha256`·`seq`·`document_id`·`observed_at` 변경, `superseded_at` 재설정, DELETE, 기존 id·`(document_id, seq)` REPLACE) / 허용 사례(`mtime_ns` 갱신, `superseded_at` NULL→값, 파서 열 갱신, `locked` 행 sha256 채우기), `scans` 표 존재, `skip_reason` 열, `versions_by_sha256` 색인, `test_id_is_the_only_unique_key_of_append_only_tables`는 **assertions·evidence에만** 적용(versions는 `UNIQUE(document_id, seq)`가 있고 그 키도 트리거로 막음을 별도 단언).

### 15.1 재검토 v2 반영 (2026-10-23)

검토 `doc/validation/2026-10-23_M1-검토_v2.md`(중간 M1-3 깊은 중첩·M1-4 속성/이름 폭탄, 낮음 L12~L14). **§15의 M1-1 행(스트리밍 `iter_xml`·`xml_max_tree_bytes`)은 아래로 대체된다.**

- **XML 읽기 방식(§5.4 대체)**: 모든 OOXML·HWPX XML 부분은 `xml.parsers.expat` 콜백으로 직접 읽는다(요소 객체·트리 없음). zip 멤버는 64 KiB 조각으로 읽어 expat에 곧바로 넣고 부분 전체를 보관하지 않는다. PPTX 슬라이드·presentation·workbook·rels도 스트림(rels는 필요한 Id의 대상만 보관). DTD는 조각마다 바이트 검사(경계 포함) + `StartDoctypeDeclHandler`로 `failed/xml_dtd`. HWP 섹션은 256 KiB씩 inflate하며 레코드를 자른다(버퍼는 미완성 PARA_TEXT 하나).
- **구조 상한(§5.3 행 추가, 모든 XML 부분)**: 깊이 256 → `too_large/xml_depth` · 요소 하나의 속성+이름공간 선언 1,000 → `xml_attributes` · 끝나지 않은 마크업(시작 태그·주석·PI)을 expat이 붙든 바이트 1 MiB → `xml_markup` · 부분 하나의 서로 다른 요소·속성 이름(접두사 포함) 10,000 → `xml_names` · 텍스트 노드 하나와 XML 단위 하나의 텍스트 8 Mi자 → `xml_text` · 파일 하나의 파싱 시간 60초 → `parse_time`. 텍스트 합(`max_text_chars`)은 읽는 도중에 확인(`limit_chars`), XLSX sharedStrings가 `max_units`개를 넘으면 `limit_units`.
- **기본값 근거**: 깊이 — 합성 생성기 실측 최대 13, 규격상 과하게 겹쳐도 100 미만, libxml2 기본 256. 속성 — Word 루트 xmlns 약 40개. 이름 — 실제 부분 수백 개. 마크업 — 긴 속성값도 수십 KB. 텍스트 — HWP 문단 상한과 같음(Excel 셀 최대 32,767자). 시간 — 이 PC 스트리밍 약 0.55 µs/이벤트, 128 MiB `<w:p/>` 28초.
- **`Limits`(§5.1)**: `xml_max_depth`, `xml_max_attributes`, `xml_max_markup_bytes`, `xml_max_names`, `xml_max_text_chars`, `parse_seconds` 추가, `xml_max_tree_bytes` 삭제(기본값만, `config.toml`로 바꾸지 않음).
- **코드(§5.6)**: too_large에 `xml_depth`, `xml_attributes`, `xml_markup`, `xml_names`, `xml_text`, `parse_time` 추가. `xml_tree`는 더 이상 발생하지 않음(옛 행 호환용으로 집합에만 남김).
- **파서 버전(§5.5)**: `docx-3`, `xlsx-3`, `pptx-3`, `hwpx-3`, `hwp-3/olefile-0.47`, `pdf-2/pypdf-6.10.0`; `text-1`, `csv-1`, `eml-2` 그대로.
- **결속(§6.2·§6.4)**: 다시 파싱한 결과가 `too_large/parse_time`이면 실패가 아니라 검증 불가 `timeout`(시간만 기계에 따라 다름). 요약 줄 끝에 `, timeout N`. 파서 버전 불일치가 1건 이상이면 안내 한 줄 `N개 버전이 다른 파서 버전으로 저장됨 — \`workmcp scan --reparse\`로 다시 파싱`.
- **재시도(§3.4)**: `too_large` 중 `parse_time`은 `--retry-failed`로, `parse_time`·`xml_tree`는 `--reparse`(파서 버전이 다를 때)로도 다시 시도. 그 밖의 `too_large`는 제외.
- **실측(적대 탐침 53개, 기본 Limits, 프로세스 피크·기저 포함)**: 최대 214 MiB(sharedStrings 상한 근처). 66 KiB DOCX 400만 단계 중첩: 2,101 MiB·1,451초 → `xml_depth` 0.0초·29 MiB. 12.6 MiB 속성 폭탄: +1,926 MiB → `xml_markup` 0.0초·41 MiB. 718 KiB XLSX 4시트: 133초 → `parse_time` 60초·30 MiB.

M5에서 실제 문서로 다시 판단. `parse_time` 경계 문서는 기계 부하에 따라 결과가 달라질 수 있다(`verify`는 `timeout`으로 격리). TXT·CSV·EML은 선형이라 시간 확인 없음.

- **형식별(그 설계 §3 표)**: XML 스트림은 이벤트 없는 조각 바이트로 마크업을 재고(`CurrentByteIndex` 폐기, expat 재파싱 유예 끔 — 1 MiB 이하 토큰은 위치와 무관하게 통과, 1.125 MiB 이상은 거부), 이름공간 선언을 `xmlns:접두사=URI` 이름으로 세어 파트 끝에 보관을 돌려준다. DOCX·HWPX 탭·줄바꿈, PPTX 빈 `a:p`·`a:br`도 텍스트로 차감하고, PPTX 표 셀은 표가 열린 동안에도 단위로 센다. XLSX 공유 문자열은 표(보관 메모리)이고 그것을 쓰는 셀마다 텍스트로 차감하며 표에 넣을 때 한 번만 strip한다. HWP 문단 텍스트는 조각 목록 없이 버퍼 하나로 모은다. PDF는 쪽 트리를 먼저 세고(중복 `/Kids` 참조 포함, 고리는 `pdf_read_error`, 트리 객체 원본 16 MiB 상한), 방문자로 연산자·글자를 세다 폼 XObject 안에서도 즉시 끊고, `/Parent` 고리 쪽·폼은 텍스트 없음으로 건너뛰며, 쪽이 끝나면 그 쪽 내용·XObject 디코드 캐시를 비운다(설계 §4.4 1단계로 충분: 20 MiB 쪽 10장·50장 모두 피크 +22 MiB). TXT·CSV·EML 줄은 64 Ki자 블록으로 지연 분할하고 CSV는 `StringIO` 사본 없이 같은 줄을 읽으며 열 번호 목록을 폭별로 공유한다. EML 메시지 파서는 8 KiB씩 시계를 보며 읽는다.

## 부록 C. HWP 섹션 레코드 생성 규칙 (C 참고)

```
def record(tag, level, payload):  # payload < 0xFFF 바이트
    return struct.pack('<I', tag | (level << 10) | (len(payload) << 20)) + payload
para(text) = record(66, 0, b'\x00'*22) + record(67, 1, text.encode('utf-16-le') + b'\r\x00')
section = b''.join(para(t) for t in texts)
stream  = zlib.compressobj(9, zlib.DEFLATED, -15) → compress(section) + flush()   # 플래그 bit0=1
FileHeader = b'HWP Document File'.ljust(32, b'\x00') + bytes([0,3,0,5]) + struct.pack('<I', flags) + b'\x00'*216
```
`extract_text._para_text`([사실] 원본)의 규칙대로 제어문자 9(탭)는 8 WCHAR를 차지하므로 탭 사례는 `'\t'` 대신 `struct.pack('<8H', 9, *[0]*7)`를 끼워 넣는다; 파서는 이를 건너뛴다(탭은 텍스트에 남지 않음 — 선언).
