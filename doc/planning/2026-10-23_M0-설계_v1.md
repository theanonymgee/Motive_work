## 1. 아키텍처

### 1.1 구성요소와 의존 방향

```
[설정·경로]  paths.py ──────────────────────────────────────────────┐
                                                                     │
[수집기] collect.py ──▶ [파서] parsers/* ──▶ [결속] binding.py        │
     │                       │                                       │
     │                       ▼                                       │
     │               units(단위 텍스트+locator)                       │
     │                       │                                       │
     │                       ▼                                       │
     │               [청크] chunks.py ──▶ [색인] index.py ◀── [임베더] embedder.py ◀── [모델] models.py (유일한 네트워크 모듈)
     │                                        │
     ▼                                        ▼
[저장소] store.py (SQLite WAL) ◀────── [검색] search.py
     ▲                                        ▲
     │                                        │
[지식] knowledge.py (엔티티·사실·결정·할 일·이력·철회·대체·충돌)
     ▲                                        ▲
     └──────────── [도구 구현] tools.py ──────┘
                        ▲
                [MCP 어댑터] server.py (mcp SDK, stdio)        [CLI] cli.py / __main__.py
```

- **[결정]** 의존은 위에서 아래로만. `server.py`는 `tools.py`만 부르고 업무 규칙을 갖지 않는다(G0 `services/mcp/server.py`의 "transport adapter, business behavior elsewhere" 원칙 유지 — [사실] 해당 파일 docstring).
- **[결정]** `tools.py`의 함수는 순수 Python(입력 dict → 출력 dict)이라 MCP 없이 테스트한다. `server.py`는 각 함수를 `@server.tool()`로 감싸기만 한다.
- **[결정]** `models.py`를 import하는 모듈은 `embedder.py`(M2), `cli.py`(`doctor`가 `quick_status`), `tools.py`(`status`가 `quick_status`)다. 어느 모듈도 `models.py`의 네트워크 함수(`download_file`, `fetch`, `main`)는 어떤 형태로도 참조하지 않는다(§7). 네트워크 함수가 아닌 함수(`entry`, `verify`, `quick_status`, `identity`, `sha256_file`, `require_verified`)만 쓴다. (검토 L-6ⓐ 반영)
- **[결정]** `knowledge.py`는 `store.py`와 `locator.py`만 의존. 검색·임베딩에 의존하지 않는다(쓰기 도구는 모델 없이도 동작).

### 1.2 프로세스 모델

- **[사실]** PLAN §6: Claude Code와 Codex가 같은 stdio 서버에 붙는다. stdio MCP는 클라이언트가 서버 프로세스를 자식으로 띄우므로 두 클라이언트가 동시에 열려 있으면 **서버 프로세스가 2개** 돈다.
- **[결정]** 따라서 상태는 전부 SQLite에 두고 프로세스 안 캐시는 임베더 인스턴스와 벡터 행렬만 둔다. 쓰기는 짧은 트랜잭션, `PRAGMA busy_timeout=5000`, WAL.
- **[결정]** stdio 서버는 **stdout에 로그를 쓰지 않는다**(stdout은 JSON-RPC 채널). 로그는 `logs/server-YYYYMMDD.log`와 stderr.
- **[결정]** 수집은 CLI `python -m workmcp scan`이 기본. 서버 도구 `refresh_sources`(M3 이후)는 같은 함수를 호출하되 `db/scan.lock`(배타 파일 생성 `O_EXCL`)로 두 프로세스 동시 수집을 막는다.
- **[제안]** 주기 수집은 Windows 작업 스케줄러 **사용자 레벨 작업**(관리자 권한 불필요)으로 `scan`을 돌린다(M5에서 확정).
- **[결정]** 임베더는 **지연 로드**: 의미 검색이 처음 요청될 때 로드. 모델 파일이 없거나 검증 실패면 어휘 검색만 하고 응답 메타에 이유를 적는다(kakao `pipeline.search_case`의 `semantic_note` 패턴 — [사실]).

### 2.2 금지 조건 (테스트 가능한 규칙)

`paths.validate_home(raw: str | None, env: Mapping, repo_root: Path | None) -> Path`가 아래 **순서**로 검사하고 위반 시 `DataPathError(code, message)`를 던진다. 코드는 테스트에서 그대로 단언한다. `raw`가 `None` 또는 빈 문자열이면 미설정으로 보고 기본값을 쓴다(Windows `set X=`가 변수를 지우는 동작과 같음 — 이탈 4).

| 순서 | 코드 | 규칙 | 판정 방법 |
|---|---|---|---|
| 0 | `home_unresolvable` | 기본값을 못 정함 | `raw` 미설정이고 `LOCALAPPDATA`가 없거나 빈 값 |
| 1 | `home_long_prefix` 처리(코드 아님) | `\\?\` 장경로 접두 | 문자열이 `\\?\X:\`(드라이브 문자) 형태면 접두를 **벗기고** 아래 검사를 계속한다. `\\?\UNC\server\share`만 UNC로 본다. (검토 L-2: 정상 로컬 장경로를 UNC로 오판하던 것을 고침) |
| 2 | `home_unc` | 네트워크 경로 금지 | (접두 처리 뒤) 문자열이 `\\` 또는 `//`로 시작, `\\.\` 장치 경로(`\??\` 접두는 구현상 `home_relative`로 거부), 또는 `PurePath.drive`가 `\\server\share` 형태. 상대 경로보다 **먼저** 본다 — `\\server\share`는 Windows에서 `is_absolute()`가 참이라 어느 순서든 막히지만 UNC를 먼저 보면 오류 코드가 정확하다(이탈 4) |
| 3 | `home_relative` | 상대 경로 금지 | `Path(raw).is_absolute()`가 거짓이면 위반(`~` 확장 안 함; 환경변수 전개 안 함). `C:`·`\x`처럼 드라이브나 루트 하나가 빠진 것도 여기 |
| 4 | `home_trailing_dot_space` | 끝 공백·점 구성요소 금지 | 어느 경로 구성요소가 공백 또는 `.`으로 끝나면 위반(`Motive_work \data`, `Motive_work.\data`). Windows가 이런 이름을 정규화하거나 `resolve()`가 `\\?\`를 붙여 뒤 검사를 흐리므로 별도 코드로 **먼저** 거부한다(검토 L-2) |
| 5 | `home_unc`(재검사) | 링크·매핑 드라이브가 네트워크로 풀림 | `home = Path(raw).resolve()` 뒤 2를 다시 본다. 정션·매핑 드라이브(`realpath`가 UNC로 풂)를 잡는다(이탈 4). 아래 검사는 모두 `home`(resolve 결과)으로 한다 |

## 3. 데이터 모델 (SQLite, WAL)

### 3.1 원칙

- **[결정]** 기준 기록 = `documents/versions/units/chunks`(원문 파생이지만 재파싱으로 재도출 가능)와 `entities/assertions/evidence`(사람이 쓴 기록). 파생 = `chunk_vectors`, `chunks_fts`. 파생 테이블은 지우고 다시 만들 수 있어야 한다(G0 명세 v3 §8 "벡터·검색용 그래프는 재생성 가능한 파생 인덱스" — [사실]).
- **[결정]** 원본 파일 복사본은 저장하지 않는다(kakao `pipeline.ingest`는 `source.txt`로 복사했음 — 여기서는 원본이 PC에 있으므로 경로+해시+추출 텍스트만 보관). 원본이 바뀌면 새 버전 행을 만들고 옛 버전의 텍스트는 유지한다.
- **[결정]** 시각은 ISO 8601 문자열(로컬 오프셋 포함, `datetime.now().astimezone().isoformat(timespec='seconds')` — kakao `pipeline._now()`와 같음).
- **[결정]** 스키마 버전은 `schema_migrations(version, name, checksum, applied_at)`(G0 `store.py` 82행 패턴 — [사실]). 적용된 마이그레이션 항목은 고치지 않고 새 항목을 덧붙인다(체크섬이 다르면 열기 거부). 다만 **v1은 실제 DB가 아직 없으므로**(테스트 DB만) 이번 검토 반영에서 v1 자체를 고쳤다.
- **[결정]** `chunks_fts`(FTS5 외부 콘텐츠 가상 테이블)는 마이그레이션 체크섬 **밖**에서, 이 Python의 SQLite에 FTS5 trigram이 있을 때만 `CREATE VIRTUAL TABLE IF NOT EXISTS`로 만든다(이탈 1). 파생 색인이고, FTS5가 없는 Python에서도 저장소가 열려야 하기 때문(§9 #14). `chunks`와의 동기화·재생성 규칙은 M2(부록 B).
- **[결정]** 마이그레이션은 **`serve` 시작 시(와 `scan` 시작 시) 한 번만** `BEGIN IMMEDIATE`로 실행한다. 도구 호출(`status` 등)은 읽기용 연결을 열고 마이그레이션·WAL PRAGMA·FTS DDL을 다시 실행하지 않는다(검토 L-9: 다른 프로세스가 긴 수집 트랜잭션을 잡고 있을 때 `busy_timeout` 5초 뒤 실패하는 것을 막음).
- **[결정]** `versions` = **관측 순서**다(내용 해시의 집합이 아님). 같은 문서에 같은 해시가 다시 와도(A→B→A: 편집 취소·백업 복원·동기화 충돌 복구) **새 행**을 만들어 되돌림 이력과 `recent_changes`의 `changed` 이벤트를 남긴다. 단위·청크·벡터는 해시(`sha256`, `text_sha256`) 기준으로 **재사용**한다(세부는 M1·M2, 검토 M-5).
- **[결정]** `assertions`는 내용 열 append-only에 더해 **상태 열의 이력도 보호**한다(검토 M-4): 종결된 행(`recorded_to`가 설정됐거나 `status IN ('withdrawn','superseded')`)은 어떤 UPDATE도 불가, `supersedes_id`는 INSERT 때만, `recorded_to >= recorded_from`, 자기 대체 금지, 상태 전이는 `active↔conflict`·`active/conflict→withdrawn/superseded`만, `change_reason`은 한 번 설정되면 불변, DELETE 금지, 기존 id로 INSERT 금지(`INSERT OR REPLACE` 우회 차단, 검토 v2 N-1 — `evidence`도 같음). 충돌 표시·해소 이력은 `links.recorded_at`·`resolved_at`에 남는다(assertion 행의 `conflict→active` 되돌림 자체는 이력을 남기지 않으므로 `links` 행이 그 기록이다). 이로써 `as_of recorded_at` 조회와 `timeline include_history`가 과거를 그대로 재생할 수 있다.

### 3.2 스키마 v1 (검토 반영판)

- **[결정]** 정확한 DDL의 기준은 `src/workmcp/store.py`다. 아래는 같은 내용을 설명용으로 옮긴 것이며, 어긋나면 코드가 우선하고 이 문서를 고친다. 도구는 `store.open_read`(읽기 전용·마이그레이션 없음)로 열고, DB가 없으면 `store_missing` 오류를 낸다(검토 L-9).

```sql
-- 연결마다: PRAGMA busy_timeout=5000; PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON;
-- schema_migrations는 마이그레이션 코드가 체크섬 밖에서 CREATE TABLE IF NOT EXISTS로 만든다.
CREATE TABLE schema_migrations(version INTEGER PRIMARY KEY, name TEXT NOT NULL,
  checksum TEXT NOT NULL, applied_at TEXT NOT NULL);

-- 아래부터 마이그레이션 1 'initial_schema_v1' (체크섬 대상)

-- 수집 대상 폴더
CREATE TABLE source_roots(id INTEGER PRIMARY KEY, path TEXT NOT NULL UNIQUE,
  enabled INTEGER NOT NULL DEFAULT 1, added_at TEXT NOT NULL);

-- 문서 = 경로 하나(대소문자 무시 키), 버전은 아래
CREATE TABLE documents(id INTEGER PRIMARY KEY, root_id INTEGER NOT NULL REFERENCES source_roots(id),
  path TEXT NOT NULL,            -- 절대 경로(표시용 원형)
  path_key TEXT NOT NULL UNIQUE, -- os.path.normcase(resolve) : NTFS 대소문자 무시
  ext TEXT NOT NULL,
  status TEXT NOT NULL CHECK(status IN ('active','deleted','skipped')),
  first_seen_at TEXT NOT NULL, last_seen_at TEXT NOT NULL, deleted_at TEXT);

-- 버전 = 관측 하나(내용 해시 + 관측 시각). 불변. 같은 문서의 최신 버전은 superseded_at IS NULL.
-- 같은 해시가 다시 와도 새 행(A→B→A 기록). UNIQUE(document_id, sha256)는 두지 않는다(검토 M-5).
CREATE TABLE versions(id INTEGER PRIMARY KEY, document_id INTEGER NOT NULL REFERENCES documents(id),
  seq INTEGER NOT NULL CHECK(seq >= 1),   -- 문서별 관측 순번 1, 2, ...
  sha256 TEXT NOT NULL, size INTEGER NOT NULL, mtime_ns INTEGER NOT NULL,
  observed_at TEXT NOT NULL, superseded_at TEXT,
  parser TEXT, parser_version TEXT, encoding TEXT,
  parse_status TEXT NOT NULL CHECK(parse_status IN ('ok','failed','locked','unsupported','too_large','encrypted','pending')),
  parse_error TEXT, unit_count INTEGER, text_chars INTEGER,
  UNIQUE(document_id, seq));
CREATE INDEX versions_sha256 ON versions(document_id, sha256);   -- 비고유. 단위·청크 재사용 조회용

-- 단위 = 파서가 만든 최소 출처 단위(쪽·시트셀·슬라이드 도형·문단·줄·메일 파트)
CREATE TABLE units(id INTEGER PRIMARY KEY, version_id INTEGER NOT NULL REFERENCES versions(id),
  ordinal INTEGER NOT NULL, kind TEXT NOT NULL,
  locator_json TEXT NOT NULL,    -- 단위 좌표만 (§3.3 unit 부분)
  text TEXT NOT NULL, text_sha256 TEXT NOT NULL,
  UNIQUE(version_id, ordinal));

-- 청크 = 단위 1개 이상을 이어 붙인 검색 단위. 문자 범위는 "단위 텍스트를 '\n'으로 이은 문자열" 기준
CREATE TABLE chunks(id INTEGER PRIMARY KEY, version_id INTEGER NOT NULL REFERENCES versions(id),
  chunk_version TEXT NOT NULL,   -- 청크 규칙 버전(예: 'units-1200-200-v1')
  ordinal INTEGER NOT NULL, unit_first INTEGER NOT NULL, unit_last INTEGER NOT NULL,
  char_start INTEGER NOT NULL, char_end INTEGER NOT NULL,
  text TEXT NOT NULL, text_sha256 TEXT NOT NULL,
  UNIQUE(version_id, chunk_version, ordinal));

-- 파생: 어휘 색인 (FTS5 trigram). 마이그레이션 체크섬 밖, FTS5가 있을 때만 생성(이탈 1). 없으면 LIKE 대체 (§8 doctor 검사)
-- CREATE VIRTUAL TABLE IF NOT EXISTS chunks_fts USING fts5(text, content='chunks', content_rowid='id', tokenize='trigram');

-- 파생: 벡터 (kakao index.py 키 구조를 chunk_id 기준으로 바꿈)
CREATE TABLE chunk_vectors(chunk_id INTEGER NOT NULL REFERENCES chunks(id),
  model_key TEXT NOT NULL,       -- sha256(canonical identity JSON)  (kakao index.model_key)
  text_sha256 TEXT NOT NULL, dims INTEGER NOT NULL, vector BLOB NOT NULL, embedded_at TEXT NOT NULL,
  PRIMARY KEY(chunk_id, model_key));
CREATE INDEX chunk_vectors_text ON chunk_vectors(model_key, text_sha256);

-- 지식: 엔티티 (사람·프로젝트·고객·조직·용어)
CREATE TABLE entities(id INTEGER PRIMARY KEY,
  kind TEXT NOT NULL CHECK(kind IN ('person','project','customer','org','term','other')),
  name TEXT NOT NULL, aliases_json TEXT NOT NULL DEFAULT '[]', note TEXT,
  created_at TEXT NOT NULL, created_by TEXT NOT NULL,     -- created_by = 클라이언트 이름(§4.1)
  merged_into INTEGER REFERENCES entities(id),            -- 병합 이력(자동 병합 없음)
  UNIQUE(kind, name));

-- 지식: 사실·결정·할 일·용어 정의 = assertion. 내용 행은 append-only; 상태 열은 아래 규칙 안에서만 갱신(검토 M-4)
CREATE TABLE assertions(id INTEGER PRIMARY KEY,
  kind TEXT NOT NULL CHECK(kind IN ('fact','decision','todo','term')),
  entity_id INTEGER REFERENCES entities(id),
  statement TEXT NOT NULL,            -- 사람이 읽는 한 문장
  data_json TEXT NOT NULL DEFAULT '{}',-- kind별 구조 필드(value/unit/period, due/done_at, definition/aliases 등)
  valid_from TEXT, valid_to TEXT,     -- 유효 시점(업무상 적용 기간, 날짜)
  recorded_from TEXT NOT NULL,        -- 기록 시점(서버 시각, 클라이언트가 못 바꿈)
  recorded_to TEXT,                   -- 철회·대체되어 현재 조회에서 빠진 시각
  status TEXT NOT NULL CHECK(status IN ('active','withdrawn','superseded','conflict')),
  supersedes_id INTEGER REFERENCES assertions(id),  -- INSERT 때만 설정(대체하는 새 행)
  change_reason TEXT,                 -- 대체·철회 이유. 한 번 설정되면 불변
  source_kind TEXT NOT NULL CHECK(source_kind IN ('evidence','my_note')),
  recorded_by TEXT NOT NULL,          -- 클라이언트 이름 + 도구 이름
  CHECK((status IN ('active','conflict')) = (recorded_to IS NULL)),  -- 열린 상태 ⇔ recorded_to 없음
  CHECK(supersedes_id IS NULL OR supersedes_id <> id));
-- (1) 종결된 행(recorded_to 설정 또는 withdrawn/superseded)은 어떤 UPDATE도 불가 → 되살리기·이유 덮어쓰기 불가
CREATE TRIGGER assertions_closed_guard BEFORE UPDATE ON assertions
  WHEN OLD.recorded_to IS NOT NULL OR OLD.status IN ('withdrawn','superseded')
  BEGIN SELECT RAISE(ABORT, 'closed assertion is append-only'); END;
-- (2) 내용 열·id·supersedes_id(INSERT 때만) 변경 불가, change_reason은 한 번 설정 후 불변
CREATE TRIGGER assertions_update_guard BEFORE UPDATE ON assertions
  WHEN NEW.statement <> OLD.statement OR NEW.data_json <> OLD.data_json OR NEW.kind <> OLD.kind
    OR NEW.entity_id IS NOT OLD.entity_id OR NEW.valid_from IS NOT OLD.valid_from
    OR NEW.valid_to IS NOT OLD.valid_to OR NEW.recorded_from <> OLD.recorded_from
    OR NEW.source_kind <> OLD.source_kind OR NEW.recorded_by <> OLD.recorded_by
    OR NEW.id <> OLD.id OR NEW.supersedes_id IS NOT OLD.supersedes_id
    OR (OLD.change_reason IS NOT NULL AND NEW.change_reason IS NOT OLD.change_reason)
  BEGIN SELECT RAISE(ABORT, 'assertion content is append-only'); END;
-- (3) 상태 전이: active↔conflict, active/conflict→withdrawn/superseded 만, recorded_to >= recorded_from
CREATE TRIGGER assertions_status_guard BEFORE UPDATE ON assertions
  WHEN NOT (NEW.status = OLD.status OR (OLD.status IN ('active','conflict')
                                         AND NEW.status IN ('active','conflict','withdrawn','superseded')))
    OR (NEW.recorded_to IS NOT NULL AND NEW.recorded_to < OLD.recorded_from)
  BEGIN SELECT RAISE(ABORT, 'assertion status change not allowed (append-only)'); END;
-- (4) DELETE 금지
CREATE TRIGGER assertions_no_delete BEFORE DELETE ON assertions BEGIN SELECT RAISE(ABORT, 'append-only'); END;
-- (5) 기존 id로 INSERT 금지: INSERT OR REPLACE/REPLACE INTO는 옛 행을 지우면서 DELETE 트리거를 건너뛴다
--     (recursive_triggers 기본 꺼짐, 검토 v2 N-1). 이 표의 고유 제약은 id 하나뿐이다. 늘리면 그 키도 막는다
CREATE TRIGGER assertions_no_replace BEFORE INSERT ON assertions
  WHEN EXISTS(SELECT 1 FROM assertions WHERE id = NEW.id)
  BEGIN SELECT RAISE(ABORT, 'append-only'); END;

-- 지식: 근거(assertion 하나에 여러 locator). source_kind='evidence'면 1행 이상 필수(knowledge.py가 강제)
CREATE TABLE evidence(id INTEGER PRIMARY KEY, assertion_id INTEGER NOT NULL REFERENCES assertions(id),
  version_id INTEGER NOT NULL REFERENCES versions(id), chunk_id INTEGER REFERENCES chunks(id),
  locator_json TEXT NOT NULL,         -- §3.3 전체 형식
  quote TEXT NOT NULL, quote_sha256 TEXT NOT NULL);
CREATE TRIGGER evidence_no_update BEFORE UPDATE ON evidence BEGIN SELECT RAISE(ABORT, 'append-only'); END;
CREATE TRIGGER evidence_no_delete BEFORE DELETE ON evidence BEGIN SELECT RAISE(ABORT, 'append-only'); END;
CREATE TRIGGER evidence_no_replace BEFORE INSERT ON evidence    -- 기존 id로 INSERT 금지(N-1, 위 (5)와 같음)
  WHEN EXISTS(SELECT 1 FROM evidence WHERE id = NEW.id)
  BEGIN SELECT RAISE(ABORT, 'append-only'); END;

-- 지식: 관계·충돌 표시
CREATE TABLE links(id INTEGER PRIMARY KEY, from_id INTEGER NOT NULL REFERENCES assertions(id),
  to_id INTEGER NOT NULL REFERENCES assertions(id),
  relation TEXT NOT NULL CHECK(relation IN ('supersedes','conflicts','supports','contradicts','relates')),
  note TEXT, recorded_at TEXT NOT NULL, recorded_by TEXT NOT NULL, resolved_at TEXT, resolved_by_id INTEGER REFERENCES assertions(id));

-- 투명성: 클라이언트로 나간 출처 기록(본문은 저장하지 않음, locator만)
CREATE TABLE deliveries(id INTEGER PRIMARY KEY, at TEXT NOT NULL, client TEXT NOT NULL,
  tool TEXT NOT NULL, locator_json TEXT NOT NULL, chars INTEGER NOT NULL);
```

- **[결정]** `assertions`의 수정 가능 열은 `status`, `recorded_to`, `change_reason`뿐이고 그것도 **열린 행**(`active`/`conflict`, `recorded_to IS NULL`)에서만, 위 (1)~(3)의 규칙 안에서만 가능하다. 트리거 (5) 때문에 기존 id를 준 `INSERT OR IGNORE`·`ON CONFLICT DO NOTHING`도 조용히 무시되지 않고 오류가 난다(검토 v3 N3-L1) — M4 쓰기 도구는 새 행을 id 없이 INSERT한다. `supersedes_id`는 대체하는 **새 행의 INSERT**에서만 설정한다. 트리거가 그 밖의 변경을 거부한다(kakao `review.py` append-only 트리거 패턴 — [사실]). 검토 §1.9가 통과시킨 네 가지(철회 행 되살림, `recorded_to`를 `recorded_from` 앞으로, 이유 덮어쓰기, 자기 대체)는 모두 거부되어야 하며 `tests/test_store_schema.py`에 거부 사례로 둔다. `source_kind='evidence'`인데 `evidence` 행이 0건인 INSERT는 스키마가 아니라 `knowledge.py`(M4)가 막는다.
- **[결정]** `links`·`deliveries`·`versions`·`entities`에는 M0에서 트리거를 두지 않는다. `links`는 충돌·대체 이력의 저장소이므로 M4에서 `knowledge.py`가 DELETE를 쓰지 않는 것으로 보호하고, 필요하면 M4 스키마 v2에서 `links_no_delete`를 추가한다(**[제안]**).
- **[결정]** `my_note`(내 메모)는 `source_kind='my_note'`로 표시하고 `evidence` 행이 없다. 응답에선 항상 "내 메모"로 표기한다.
- **[결정]** 충돌: 같은 `entity_id`·`kind`·`data_json.key`(사실의 경우)·겹치는 유효 기간의 `active` 행이 둘 이상이 되면 서버가 두 행 모두 `status='conflict'`로 바꾸고 `links(relation='conflicts')`를 만든다. 자동으로 한쪽을 버리지 않는다(G0 명세 v3 §8 "단순 최신 우선으로 삭제하지 않음" — [사실]). 사람이 `supersede` 또는 `withdraw`로 해소하면 `resolved_at`을 적는다.
- **[결정]** 시점 조회 규칙(G0 `entities.entities_at` — [사실]): `valid_from <= valid_at < valid_to(없으면 무한)` **그리고** `recorded_from <= recorded_at < recorded_to(없으면 무한)`. 기본은 `valid_at = recorded_at = now`.
- **[결정]** 엔티티 자동 병합 없음. `aliases_json`에 별칭을 명시하고, 병합은 `merge_entities` 도구(M4)로 사람이 한다(`merged_into`). 명세 v3 §7 "같은 문자열을 같은 개체로 자동 병합하지 않는다" — [사실].
- **[제안]** `data_json` 구조(M4에서 확정): fact `{key, value, unit, period}`; todo `{due, done_at, owner}`; term `{definition, aliases, scope}`; decision `{options, chosen, rationale}`.

### 3.3 출처 좌표(locator) 형식

**[결정]** 하나의 locator는 아래 JSON 객체. `evidence.locator_json`, 모든 도구 응답의 `locator`, `deliveries`에 같은 형식을 쓴다.

```json
{
  "v": 1,
  "doc": 123,                               // documents.id
  "path": "D:\\work\\계약\\A사_제안_v3.docx",          // 합성 예시 경로
  "sha256": "3f9a…(64 hex)",                // versions.sha256 : 그 버전의 파일 전체 해시
  "unit": {"kind": "paragraph", "index": 12},
  "chars": [120, 340],                      // 단위 텍스트 안 [start, end) 문자 오프셋(0-based, Python 슬라이스)
  "text_sha256": "…(64 hex)"                // text[start:end]의 UTF-8 SHA-256
}
```

`unit` 종류(파서가 정함, M1 확정):

| kind | 필드 | 파서 |
|---|---|---|
| `line` | `line`(1-based) | TXT·MD |
| `cell` | `row`(1-based), `columns`[1-based 목록] | CSV |
| `page` | `page`(1-based) | PDF |
| `paragraph` | `index`(1-based, 문서 순서), `table`·`row`·`column`(표 셀이면) | DOCX, HWP, HWPX |
| `slide` | `slide`, `shape` | PPTX 도형 |
| `slide_cell` | `slide`, `shape`, `row`, `column` | PPTX 표 |
| `sheet_cell` | `sheet`(이름), `cell`(`B12`) | XLSX |
| `mail_header` | — | EML |
| `mail` | `part`, `line` | EML 본문 |
| `section_para` | `section`, `index` | HWP(섹션 단위) |

- **[결정]** 한 줄 표시 문자열(사람·클라이언트가 읽는 용): `"{path} @ {sha256[:12]} / {unit_label} / chars {start}-{end}"` 예: `D:\work\계약\A사_제안_v3.docx @ 3f9a1c2b4d5e / 문단 12 / chars 120-340`. 저장은 JSON으로만.
- **[결정]** M0의 `locator.py`는 DB 없이 할 수 있는 검사만 갖는다: `check_shape`(필드·형식·hex 길이·`v`는 `int` 타입 1 — `True`·`1.0` 거부, 검토 L-10)와 `check_text`(범위·`text_sha256`). DB 대조 `validate(obj, store)`(버전·단위 존재)는 단위 행이 생기는 **M1**로 미룬다(이탈 5).
- **[결정]** `chars` 범위는 **단위 텍스트** 안의 오프셋이다(문서 전체 오프셋 아님). 이유: 단위 텍스트는 파서 버전이 같으면 재도출 가능하고 짧아서 결속 검사가 싸다. 청크의 `char_start/char_end`는 "단위들을 `\n`으로 이은 문자열" 기준이며 응답에선 항상 단위 locator로 환산한다.
- **[결정]** `source_coordinates.py`와의 관계: 그 모듈은 "단위 텍스트에서 낱말 번호 범위 `[w_first, w_last]`를 문자 범위와 인용 해시로 바꾸는" 변환기다([사실] `anchor()`가 `{'w','start','end','text_sha256'}` 반환). 이식한 `locator.py`는 (a) 클라이언트가 `quote` 문자열을 주면 단위 텍스트에서 위치를 찾아 `chars`를 만들고, (b) 낱말 범위 `w`를 주면 `anchor()`로 `chars`를 만든다. 둘 다 결과는 위 locator 하나. 낱말 토큰화 규칙(`_WORD`, `_LINE_BREAK`, `_SENTENCE_END`)은 그대로 쓰고 `TOKENIZER_VERSION='unit-words-sentences-v1'`을 `COORD_VERSION`으로 이름만 바꾼다. 모델 입력 렌더링 `render()`는 버린다(G0의 LLM 좌표 선택용).
- **[결정]** locator 검증(`locator.validate(obj, store)`): 필드·형식(hex 길이) → 버전 존재 → 단위 존재 → `0 <= start < end <= len(unit.text)` → `sha256(text[start:end]) == text_sha256`. 하나라도 틀리면 `LocatorError(code)`(`coordinate_shape_invalid`, `coordinate_reversed`, `coordinate_out_of_range`는 `source_coordinates.CoordinateError` 코드 재사용 — [사실]).

## 4. MCP 도구 목록과 입출력

### 4.1 공통 규칙

- **[결정]** 모든 응답은 봉투 `{"ok": true, "result": …, "delivered_sources": [locator 표시 문자열…], "notice": [문장…]}` 또는 `{"ok": false, "error": {"code", "message", "retryable": false}}`(G0 `mcp/server.py` 오류 형식 — [사실]). `delivered_sources`는 **이번 응답에 본문(원문 조각·인용)이 실려 나간 출처만** 나열한다(PLAN §6). 목록만 돌려준 문서는 들어가지 않는다.
- **[결정]** 서버는 응답을 만들 때 `deliveries`에 같은 목록을 적는다(본문 저장 안 함). `client`는 MCP `initialize`의 `clientInfo.name`(Claude Code / Codex 등) — **[추정]** mcp 2.2.0 서버 API에서 세션의 클라이언트 정보를 읽는 방법은 실행자가 확인; 못 읽으면 CLI 인자 `serve --client <name>`으로 설정 파일에 명시.
- **[결정]** 쓰기 도구는 `recorded_by = "<client>/<tool>"`을 기록하고 `recorded_from`은 서버 시각. 클라이언트가 보낸 시각은 `valid_from/valid_to`에만 쓴다.
- **[결정]** 응답 크기 상한: 조각 하나 최대 4,000자, 응답 전체 최대 60,000자(초과 시 `notice`에 잘림 표시). 숫자는 M3에서 조정 가능.
- **[결정]** 도구 이름은 snake_case, 입력은 JSON Schema(SDK가 타입 힌트에서 생성). Claude Code·Codex 둘 다 같은 서버·같은 도구.

### 4.3 쓰기 도구 (M4; 스키마는 M0, 구현은 M4)

공통 입력 `evidence: list[Evidence]` **또는** `my_note: true` 중 정확히 하나. `Evidence = {chunk_id: int, quote: str}` 또는 `{locator: object}` 또는 `{chunk_id, w: [first, last]}`(낱말 범위). 서버가 `quote`를 그 청크의 단위 텍스트에서 찾아 locator로 확정하고, 못 찾으면 `evidence_quote_not_found`로 거부한다. 둘 다 없거나 둘 다 있으면 `evidence_required`.

| 도구 | 입력 | 출력 | 오류 |
|---|---|---|---|

| `record_todo` | `statement`, `entity?`, `due?`, `owner?`, `evidence|my_note` | `assertion` | 같음 |

| `record_term` | `term`(엔티티 kind=`term`을 없으면 생성), `definition`, `aliases?`, `scope?`, `evidence|my_note` | `entity`, `assertion` | 같음 |

| `supersede` | `old_id`, 새 내용(`statement`, `data`, `valid_from?`, `valid_to?`), `reason`(필수), `evidence|my_note` | `old`(status `superseded`, `recorded_to`), `new`(`supersedes_id=old_id`), `links(supersedes)` | 같음 |

## 5. 증분 수집 방식 (M1)

- **[결정]** 1차 감지: 각 파일의 `(size, mtime_ns)`를 `versions` 최신 행과 비교. 같으면 건너뛰고 `documents.last_seen_at`만 갱신. 다르면 2차: 스트리밍 SHA-256(1 MiB 블록, kakao `models.sha256_file` 패턴 — [사실]). 해시가 **최신 버전**과 같으면(mtime만 바뀐 경우) 최신 버전의 `mtime_ns`만 갱신(버전 추가 안 함). 다르면 **무조건 새 `versions` 행** + 옛 최신 행 `superseded_at` — 같은 해시의 옛 버전이 이미 있어도(A→B→A) 새 행을 만든다(§3.1, 검토 M-5). 그 경우 단위·청크는 `versions_sha256` 색인으로 같은 해시·같은 `parser_version`의 옛 버전을 찾아 **재파싱 없이 복사**(단위 텍스트는 `text_sha256`이 같으므로 벡터도 `chunk_vectors_text` 색인으로 재사용), `recent_changes`에는 `changed`로 나타난다.
- **[결정]** 삭제: 전체 스캔이 끝난 뒤 이번 스캔에서 보이지 않은 `active` 문서를 `deleted`로 표시(`deleted_at`). 버전·단위·청크·근거는 보존. 다시 나타나면 `active`로 되돌리고 해시 비교로 버전 결정. 부분 스캔(`--root` 하나)에서는 그 루트 안에서만 삭제 판정.
- **[결정]** 버전 보존: 텍스트(`units.text`)는 버전마다 유지. 용량이 걱정되면 M2 이후 "옛 버전 청크의 벡터만 삭제"(파생) 옵션. 원본 복사 없음.
- **[결정]** 대용량 폴더: `os.scandir` 재귀, 기본 제외 `{'.git','node_modules','.venv','venv','__pycache__','$RECYCLE.BIN','System Volume Information'}`와 패턴 `~$*`(Office 잠금 파일), `*.tmp`, `.~lock*`. 파일 크기 상한 기본 100 MiB(`parse_status='too_large'`, 해시는 계산). 파일 N=200개마다 `commit`, 중단 시 다음 스캔이 이어서(버전 행이 이미 있으면 재파싱 안 함). 파싱은 파일 단위로 실패를 격리(`parse_status='failed'`, `parse_error`에 예외 종류·메시지 앞 200자, 본문 없음).
- **[결정]** 잠긴 파일: `open(path, 'rb')`에서 `PermissionError`/`OSError(errno 13, 32)`면 `parse_status='locked'`, 다음 스캔에서 재시도. 열린 Office 파일은 보통 공유 읽기가 허용되지만 Excel은 배타 잠금이 있을 수 있음 — [추정], M1에서 확인.
- **[결정]** 인코딩(텍스트 계열): `utf-8-sig` → 실패 시 `cp949` → 실패 시 `utf-16`(BOM 있을 때만) → 모두 실패면 `parse_status='failed'`, `parse_error='encoding_unknown'`. 성공한 이름을 `versions.encoding`에 기록. `\x00` 포함 시 바이너리로 보고 거부(G0 `parsing` — [사실]). kakao `read_raw`는 UTF-8만 받고 BOM·CRLF를 기록한다([사실]) — CP949 분기만 더한다. 줄 번호는 `\r\n`·`\n` 모두 한 줄로 센다.
- **[결정]** 원본 읽기 전용 보장 — 세 겹:
  1. 코드 규칙: `collect.py`·`parsers/*`·`binding.py`는 원본 경로에 대해 `open(..., 'rb')`만 쓴다. `os.remove/unlink/rename/replace/utime/chmod`, `shutil.move/copy*`, `Path.write_*`, `Path.touch` 호출 금지.
  2. 정적 테스트(M1): AST로 위 모듈에서 금지 호출과 `open()` 두 번째 인자에 `'w'|'a'|'+'|'x'`가 들어가는 호출을 찾아 0건 단언(쓰기는 `store.py`·`models.py`·`cli.py`에만 허용).
  3. 런타임 테스트(M1): `sys.addaudithook`으로 `open` 이벤트 중 mode에 `w/a/+/x`가 있고 경로가 테스트용 원본 폴더 하위인 것, `os.remove/os.rename/shutil.move` 이벤트를 수집해 스캔·파싱·결속 전 과정에서 0건 단언(kakao `test_runtime_path_opens_no_evaluation_file_socket_or_process` 패턴 — [사실]).
- **[결정]** 결속 검사(`binding.verify_version(version_id)`): 현재 파일 해시가 `versions.sha256`과 같을 때만 수행 → 같은 `parser_version`으로 재파싱 → 단위 수·각 단위 `text_sha256` 일치 → 청크 텍스트 재구성 일치 → 그 버전을 가리키는 `evidence.quote_sha256` 일치. 결과 `{total, bound, rate, ok, failures[:20], scope}`(kakao `verify_binding` 반환 형식 — [사실]). M1 완료 기준 "결속 100%"는 합성 문서 묶음에서 `ok=True`.

## 7. 네트워크 경계

### 7.1 규칙

- **[결정]** 허용 목록의 기준은 `tests/test_network_boundary.py`(`COMMON_IMPORTS`·`MODULE_IMPORTS`·`FUNCTION_IMPORTS`)다. 이 절의 공통 허용 모듈 나열은 M1·M2에서 추가할 **후보**이며, 실제 목록은 구현이 쓰는 것과 정확히 같아야 한다(`test_allowlists_match_the_sources_exactly`). `workmcp` 절대 import는 위반(상대 import만). 런타임 판정은 `localhost` 문자열·`::ffff:127.0.0.1`·`0.0.0.0`과 모든 이름 해석(`getaddrinfo` 등)을 거부한다(이 절의 서술보다 엄격, 검토 v2 N-L6). 어긋나면 테스트가 우선하고 이 문서를 고친다.
- **[결정]** 패키지 `workmcp` 소스에서 네트워크·프로세스 모듈을 import하거나 참조하는 모듈은 **`models.py` 하나**. `models.py` 안에서도 네트워크 import는 함수 안(`download_file`)에서만 하고, 모듈 import 시 네트워크 코드가 로드되지 않게 한다(kakao `models.py` docstring의 "httpx is imported inside the download function" 원칙 — [사실]).
- **[결정] 정적 검사는 허용 목록(allowlist) 방식이다.** 금지 목록 방식은 부족했다: 검토 §1.7에서 우회 snippet 29개 중 **27개가 미검출**(`import os as o`, `getattr(os,'system')`, `import nt/_winapi/_socket/ctypes`, `exec/eval`, `pkgutil.resolve_name`, `runpy`, `sys.modules[...]`, 설치돼 있는 `uvicorn`·`starlette`·`httpcore2`, 표준 `socketserver`·`wsgiref`·`nntplib` 등). 이름을 하나씩 막는 방식은 설치된 패키지·표준 라이브러리가 바뀔 때마다 구멍이 생기므로, **모듈마다 import해도 되는 최상위 이름을 정하고 그 밖은 전부 위반**으로 본다.
  - 공통 허용(모든 모듈): `__future__`, `argparse`, `collections`, `dataclasses`, `datetime`, `enum`, `functools`, `hashlib`, `importlib.metadata`(이 하위 모듈만; `importlib` 자체·`importlib.util` 불허), `itertools`, `json`, `logging`, `math`, `os`, `pathlib`, `platform`, `re`, `sqlite3`, `string`, `sys`, `textwrap`, `time`, `tomllib`, `typing`, `unicodedata`, `zlib` + 패키지 안 상대 import(`from . import x`, `from .x import y`). `workmcp` 절대 import는 위반. (이 나열은 후보이고 현재 구현의 공통 목록은 12개뿐이다 — 위 [결정] 참고.) ### 7.2 서드파티(mcp SDK)가 네트워크 라이브러리를 import하는 문제

- **[사실]** `mcp 2.2.0`의 `Requires-Dist`: `httpx2`, `starlette`, `sse-starlette`, `uvicorn`, `anyio`, `pyjwt[crypto]`, `pywin32`(win32) 등. 즉 설치하면 HTTP 서버·클라이언트 코드가 함께 들어오고 `import mcp` 시 일부가 import될 수 있다.
- **[결정]** 경계의 정의를 두 층으로 둔다. (1) **우리 코드가** 네트워크 라이브러리를 쓰지 않는다(§7.1 정적 허용 목록). (2) **런타임에 loopback(127.0.0.1/::1) 외 주소로 가는 소켓 연결·bind·이름 해석이 0건**이다. loopback은 **asyncio 이벤트 루프 내부용으로만** 허용한다. 서드파티 소스는 AST 검사 대상이 아니다(site-packages 스캔은 하지 않음 — 거짓 양성만 늘고 보증은 못 함).
  - **[사실]**(검토 §1.5 실측) Windows에서 `serve`를 실제로 돌리면 asyncio 이벤트 루프(`ProactorEventLoop`)가 내부 알림용(self-pipe) **loopback 소켓 쌍**을 만든다: `socket.bind(('127.0.0.1', 0))` 1건, `socket.connect(('127.0.0.1', <포트>))` 1건, `socket.__new__` 2건. 외부 주소로 가는 이벤트는 없다. 따라서 v1 초안의 "런타임에 소켓 연결 0건"은 Windows에서 사실이 아니어서 정의를 위와 같이 고쳤다(검토 M-2).
  - 판정 방법: audit hook이 `socket.connect`·`socket.bind`·`socket.connect_ex`·`socket.sendto`·`socket.sendmsg`·`socket.getaddrinfo`·`socket.gethostbyname`·`socket.gethostbyaddr`·`socket.getnameinfo` 이벤트의 **주소 인자**를 기록하고, 테스트는 주소의 호스트가 모두 `127.0.0.1`·`::1`임을 단언한다(`localhost` 문자열·`::ffff:127.0.0.1`·`0.0.0.0`은 위반, `getaddrinfo`/`gethostbyname` 등 이름 해석은 0건). `http.client.connect`, `urllib.Request`, `subprocess.Popen`, `os.system`, `os.exec*`, `os.spawn*`, `os.startfile`은 주소 무관 0건.
- **[결정]** 런타임 층 테스트 A — **import 경로**(M0): 새 인터프리터에서 `sys.addaudithook`을 걸고 `workmcp`의 모든 모듈을 import(`pkgutil.walk_packages`)하고 `server.build_server(home)`를 만들고 `tools.status(home)`를 부른 뒤 위 판정을 적용. **[사실]**(실행자·검토자 측정 2026-10-23, Python 3.12.13·mcp 2.2.0·Windows 11) 이 경로에서는 감시 접두 이벤트가 **하나도** 없어 허용 목록은 빈 집합이다. 양성 대조군: 같은 hook이 `socket.socket()` 생성을 기록하는지 확인.
- **[결정]** 런타임 층 테스트 B — **serve 경로**(원래 M3 예정이었으나 **M0에 당겨 넣음**, 검토 M-2·L-12): 서버 프로세스를 `python tests/_audited_server.py`(audit hook을 설치한 뒤 `workmcp.server.main()`을 부르는 테스트 전용 래퍼)로 띄우고 stdin으로 `initialize`→`notifications/initialized`→`tools/list`→`tools/call status`를 보낸 뒤 stdin을 닫는다. 단언: (a) 종료 코드 0, (b) **stdout의 모든 줄이 JSON-RPC**(파싱되고 `jsonrpc` 키가 있음, 비-JSON 줄 0건 — stdout 순수성), (c) 세 응답이 각각 `serverInfo.name == 'workmcp'`, `status` 도구 포함, `ok: true`를 담음, (d) 래퍼가 stderr(또는 임시 파일)에 기록한 소켓 이벤트가 위 판정(loopback만)을 통과. 래퍼는 `tests/`에 있으므로 패키지 AST 검사 대상이 아니다. 거부 경로(위반 홈)의 빈 stdout 테스트는 그대로 둔다.
- **[결정]** M5 보안 점검표의 "외부 전송 0 확인 방법"도 같은 정의를 따른다: 회사 PC에서 `tests/_audited_server.py`와 같은 방식으로 serve를 한 번 돌려 loopback 외 주소 이벤트 0건을 기록하고, 가능하면 `netstat -ano`/리소스 모니터로 서버 PID의 원격 연결이 없음을 교차 확인한다(§9 #10).
- **[결정]** `uv.lock`에서 금지 패키지 검사는 하지 않는다(`httpx2`는 mcp의 필수 의존). 대신 **직접 의존성**에 네트워크 클라이언트(`httpx`, `requests`, `aiohttp`, `huggingface_hub`)가 들어가면 테스트 실패: `pyproject.toml`의 `[project].dependencies`를 파싱(`tomllib`)해 금지 이름이 없음을 단언.

### 8.2 의존성과 lock

- **[사실]** 이 PC: `uv 0.11.24` 설치됨, uv 관리 Python `3.12.13` 존재(`%APPDATA%\uv\python\cpython-3.12.13-windows-x86_64-none`), Git Bash 기본 `python`은 3.11.15. 관리자 권한 없이 모두 사용자 레벨.
- **[결정]** 도구: **uv**. `uv venv --python 3.12`, `uv lock`, `uv sync --frozen`. lock 파일 `uv.lock` 커밋. 회사 PC에서 uv가 막힐 경우 대비로 `uv export --format requirements-txt --hashes --no-emit-project -o requirements.lock.txt`도 커밋해 `python -m pip install --require-hashes -r requirements.lock.txt` 뒤 `python -m pip install --no-deps --no-build-isolation -e .`로 설치 가능하게 한다(둘 다 관리자 권한 불필요). `--no-emit-project`인 이유: editable 프로젝트 줄에는 해시를 붙일 수 없어 `--require-hashes`와 함께 쓸 수 없다(이탈 3). `requirements.lock.txt`에 dev 그룹(`pytest`)이 포함되는 것은 **의도**다(회사 PC에서도 테스트를 돌려 설치를 검증하기 위함 — 검토 L-4; `CLAUDE.md` Commands 절에도 적음). pip의 해시 고정만 쓰는 안은 해석기가 없어 갱신이 번거로워 채택하지 않음.
- **[사실]**(검토 §1.4) `uv.lock` 37개(레지스트리 36 + editable 1)·`requirements.lock.txt` 36개 전부 해시 있음, 모든 패키지에 `win_amd64` 또는 `py3-none-any` 휠 있음, `requires-python = "==3.12.*"`.
- **[결정]** M0 직접 의존성: `mcp==2.2.0`(Motive_vari lock과 같은 버전 — [사실]). 개발 그룹 `[dependency-groups] dev = ["pytest==9.1.1"]`.

## 10. 열린 질문 (피터 승인이 필요한 것만)

- **M0 범위: 없음.** 아래는 PLAN §6 보류 항목에 닿는 질문으로, 해당 Phase에서 묻는다.

그 밖에 설계자가 정한 것(패키지 이름 `workmcp`, uv+uv.lock, pytest, `urllib` 전환, pypdf 우선, FTS5 trigram, 응답 봉투·크기 상한)은 총괄이 PLAN에 반영하거나 되돌릴 수 있다.

## 부록 A. 용어

- **단위(unit)**: 파서가 만드는 최소 출처 단위(쪽·셀·슬라이드 도형·문단·줄). locator의 `unit`.
- **청크(chunk)**: 검색 단위. 단위 1개 이상의 연속. 응답은 항상 단위 locator로 환산.
- **결속(binding)**: 저장된 단위·청크·인용이 같은 파서 버전으로 현재 파일에서 재도출됨. 파서가 맞는지는 보증하지 않음(kakao `binding.SCOPE` 문구 계승).
- **유효 시점/기록 시점**: 업무상 적용 기간 / 서버가 알게 된 기간(명세 v3 §8).
- **내 메모(my_note)**: 출처 없이 피터(클라이언트)가 적은 기록. 항상 그렇게 표시.
