## 1. 무엇을 만드는가

피터가 **회사 PC**에서 쓰는 Claude Code·Codex(및 다른 MCP 클라이언트)에 붙이는 **개인용 업무 지식 MCP 서버**다. 회사 PC의 업무 문서를 읽어 원문 근거와 묶인 검색 가능한 지식으로 만들고, 사람·프로젝트·고객·용어·결정·할 일 같은 구조화 지식과 시간 이력을 쌓는다. 판단과 글쓰기는 MCP 클라이언트가 하고, 서버는 수집·근거 결속·검색·이력을 맡는다. 단일 사용자 개인용이다.

이 프로젝트는 형제 프로젝트 `../Motive_vari`의 원래 의도(G0)를 가볍게 다시 시작한 것이다. 재사용할 코드는 `Motive_vari`의 태그 `kakao-p1-complete-20261022`(로컬 파서·원문 결속·BGE-M3 ONNX 임베딩·혼합 검색, 이 PC에서 검증됨)와 `g0-freeze-20261017`(G0 파서·검색·MCP 패턴·관계·시간 이력 개념)에 있다. **필요한 것만 골라 이식**하고, G0의 합성 인증·평가 하네스·의사결정 작업대·카톡 전용 결합은 가져오지 않는다. `Motive_vari` 저장소는 읽기만 하고 고치지 않는다(그쪽 개발 세션이 별도로 진행 중).

## 3. 목표 운용 (/goal)

- 목표는 Phase 단위다. 첫 턴에 PLAN.md §4의 `/goal` 문구를 피터에게 보여 주고 등록을 요청한다(이미 있으면 `/goal`로 확인).
- `/goal` 평가기는 대화에 드러난 것만 본다. 완료 조건마다 실제 명령 출력·파일 경로·검토 결과를 대화에 그대로 보인다.
- Phase 완료 시: PLAN.md §5에 완료 근거, §4를 다음 Phase로, §9에 한 줄, PROGRESS 갱신, 커밋·푸시, 피터에게 다음 `/goal` 문구 제시. 피터가 새 goal을 등록하기 전에는 다음 Phase 코드를 시작하지 않는다.
- 승인이 필요한 항목(PLAN.md §6 보류)에 닿으면 멈추고 번호로 묻는다. 기다리는 동안 독립 작업은 진행한다. 이미 답한 것은 다시 묻지 않는다.

## 4. 팀과 모델

역할 이름은 총괄·설계자·실행자·검토자·조사만 쓴다. 모두 Claude 계열 서브에이전트로 띄우고, 역할·읽을 문서·쓸 파일·금지 사항·보고 형식을 명시한다. 동시 실행자 최대 3, 같은 파일에 둘 금지.

| 역할 | 모델 |
|---|---|
| 총괄(당신) | 세션 본체 Opus 5.5 |
| 설계자 | **Fable 5.1, effort high** — 문서로만 답, 코드·외부 접촉 금지 |

## 5. 제약 (AGENTS.md가 권위)

- 원문·텍스트·색인·임베딩은 PC 로컬, 저장소 밖(기본 `%LOCALAPPDATA%\Motive_work\`), 동기화 폴더 금지. 서버의 외부 AI/API 호출 0. 임베딩은 CPU 로컬(ONNX Runtime). 네트워크를 쓰는 모듈은 모델 다운로드 하나뿐 — 테스트로 고정.
- 회사 자료는 git·테스트·문서·로그·이슈에 넣지 않는다. 개발·테스트는 합성·공개 문서만. 실제 회사 자료는 M5 이후 회사 PC에서만.
- 원본 파일은 읽기 전용. 모든 응답 조각과 구조화 사실에 정확한 출처(파일·버전 해시·쪽/시트/줄 또는 글자 범위). 출처 없는 쓰기는 "내 메모"로만.
- 관리자 권한 가정 안 함. 비밀값은 `.env`만. 신규 유료 지출 없음.
- 커밋 메시지·코드 주석에 모델 식별자 금지.

## 6. 즉시 중단·보고

회사 자료나 비밀값이 저장소에 들어갈 뻔함 · 서버에 외부 호출 추가 · 원본 파일 쓰기 시도 · 같은 작업 등급 3 실패 · 신규 지출 필요. 멈추고 기록하고 피터에게 보고한다.

## 7. 기록과 커밋

- 작업 단위마다 `docs/PROGRESS.md` 최상단에 한 줄 이상. 설계·검토·실측은 `doc/`에 `yyyy-mm-dd_파일명_vN.md`로, `doc/2026-10-22_문서목록_v1.md`에 추가.
