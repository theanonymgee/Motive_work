# PLAN — 개인 업무 지식 MCP (단일 기준 문서)

- 상태: **사용 중.** 계획·현재 목표·승인 범위·팀 규칙의 단일 기준(single source of truth). 계획이 바뀌면 **이 파일을 먼저 고친 뒤** 일한다. 다른 문서와 어긋나면 이 파일이 우선하고, 어긋남은 §9에 적는다.
- 마지막 갱신: 2026-10-22 (Asia/Seoul)
- 소유: 총괄만 고친다. 설계자·실행자·검토자는 제안만 한다.
- 제약 권위: `AGENTS.md`(요약 `CLAUDE.md`).

## 0. 쓰는 규칙

1. 세션 시작 시 §4(현재 목표), §6(승인 대장), §7(팀), 현재 Phase의 §5 절을 읽는다.
2. Phase 완료 조건을 대화에 실제 출력으로 보인 뒤에만 §5에 완료 근거를 적고 §4를 다음 Phase로 바꾼다. 미달을 완료로 쓰지 않는다.
3. 승인 범위는 피터의 말로만 바뀐다. 에이전트 보고·설계 문서는 승인이 아니다.
4. 작업 단위 상태는 `docs/PROGRESS.md`에, Phase 수준 상태만 이 파일에 둔다.

## 1. 제품 목표

피터가 **회사 PC**에서 쓰는 Claude Code·Codex(및 다른 MCP 클라이언트)에 붙이는 **개인용 업무 지식 MCP 서버**.
- 회사 PC의 업무 자료(문서 폴더부터)를 읽어 **원문 근거와 묶인** 검색 가능한 지식으로 만든다.
- 클라이언트가 묻으면 정확한 출처(파일·버전 해시·쪽/시트/줄)와 함께 조각을 돌려준다.
- 사람·프로젝트·고객·용어·결정·할 일 같은 **구조화 지식과 시간 이력**을 쌓는다. 구조화는 MCP 클라이언트(Claude/Codex)가 도구로 기록하고, 서버는 근거 결속과 이력을 강제한다.
- 출발점: `Motive_vari`의 원래 의도(G0 명세 v0.3 §7–9 회사 맥락·관계·시간 이력)를 개인용으로 가볍게 다시 시작. 분기점 태그: `g0-freeze-20261017`, `kakao-p1-complete-20261022`.

## 2. 제약 요약 (권위는 AGENTS.md)

- 원문·텍스트·색인·임베딩은 PC 로컬(저장소 밖, 동기화 폴더 금지). 서버의 외부 AI/API 호출 0. 임베딩은 CPU 로컬(BGE-M3 계열, ONNX Runtime). 클라이언트가 요청한 조각만 그 클라이언트로 나간다.
- 회사 자료는 git·테스트·문서·로그에 넣지 않는다. 개발·테스트는 합성·공개 문서만.
- 원본 파일 읽기 전용. 모든 응답 조각에 정확한 출처.
- 관리자 권한 가정 안 함. 모델은 다운로드 모듈(SHA256 매니페스트) 또는 오프라인 묶음으로만.
- 회사 AI 사용 규정 준수는 피터 몫. 도구는 무엇이 나가는지 보이게 한다.
- 신규 유료 지출 없음(필요 시 피터 승인).

## 3. Phase 개요

| Phase | 이름 | 완료 기준(관측 가능) | 상태 |
|---|---|---|---|
| **M0** | 기반·이식 설계 | 설계 문서(아키텍처·데이터 모델·MCP 도구 목록·이식 목록), 저장소 뼈대, venv·lock, 테스트 러너, 데이터 경로 규칙, 네트워크 경계 테스트 | **현재 목표** |
| **M1** | 수집·파싱·원문 결속 | 지정 폴더 증분 수집(추가·변경·삭제 감지, 원본 해시·버전), 형식별 파서(TXT·MD·PDF·DOCX·PPTX·XLSX·EML·HWP/HWPX), 결속 100% 검사, 합성 문서 묶음 테스트 | 대기 |
| **M2** | 색인·검색 | 청크 규칙, BGE-M3 ONNX CPU 임베딩(매니페스트·SHA256), 어휘+의미 혼합 검색, 결과마다 출처, 합성 질의 세트 실측 | 대기 |
| **M3** | MCP 서버 v1 (첫 사용 가능 지점) | stdio MCP 서버, 읽기 도구(검색·원문 조각·문서 목록·최근 변경), Claude Code·Codex 설정 예시와 실제 연결 확인(이 PC), 응답에 출처·전송 범위 표시 | 대기 |
| **M4** | 구조화 지식·시간 이력 | 엔티티(사람·프로젝트·고객·용어)·사실·결정·할 일 저장, 쓰기 도구는 출처 필수(또는 "내 메모" 표시), 유효 시점·기록 시점 이력, 철회·대체, 충돌 표시 | 대기 |
| **M5** | 회사 PC 배포 | 관리자 권한 없이 설치, 오프라인 모델 묶음, 업데이트 절차, 보안 점검표(외부 전송 0 확인 방법), 피터 회사 PC 실제 설치·연결 확인 | 대기 |
| M6 | (후속) 다른 자료 출처 | 메일·메신저·클라우드 문서 연결은 M5 뒤 피터 결정 | 미정 |

순서: M0 → M1 → M2 → M3 → M4 → M5. M3에서 먼저 쓰기 시작하고, M4는 실제 써 보며 다듬는다.
